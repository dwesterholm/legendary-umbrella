# Phase 14.4 Plan 02: Sold-page enrichment (v2) Summary

**The sold-price cache now stores avgift, BRF id, tenure, days on market, first price and photo ids; 1 200 recent sales and 787 housing associations were read through the free local browser with no failed page, no Booli block page and no Apify cost.**

## What this means for Daniel

Plan 03 now has what it needs: avgift on 1 192 sold flats, debt per m² on 1 014 of them (1 009 with both), enough for the standard errors the research asked for.

The first attempt had stopped itself after 50 pages. The rule counted 3 empty pages as failures; they were sales at Booli's one-year cutoff, not blocking. The coordinator amended the rule (R-10): an empty page is now counted as `no_data`, a real failure is counted only when the page fails to load, the check starts after 100 attempts instead of 50, and a Booli challenge page still stops the run at once. The window then moved to sales from 2025-10-20, and the batch ran to the end.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Stratified draw made fixed so a resume does not extend the sample**
- **Found during:** Task 2
- **Issue:** As worded, the stratified sample was drawn from rows still due, so a resume would have drawn another 1 200.
- **Fix:** With `--stratify` the draw covers every row of the window (finished ones included) and finished rows are dropped afterwards. A unit test pins it. It worked as intended: the rerun picked 1 150 rows because 52 of the 1 200 were already done.
- **Committed in:** 6c435b1

**2. [Rule 2 - Missing critical] Guards the plan did not spell out**
- The BRF pass throws unless the renderer is local and `--allow-apify` is absent.
- `enrichSoldRows` throws if given a ledger without `today`.
- The dry-run cost line no longer prints a misleading Apify estimate when the renderer is local.
- **Committed in:** 6c435b1

**3. [Rule 1 - Bug] `budgetExceeded` signature widened**
- It now receives `{attempted, failed}` so the stop rule can live in the pure module; old `() => boolean` callers still work.
- **Committed in:** 6c435b1

**4. Orchestrator decision R-10 (not an executor deviation)**
- Stop rule amended after the first halt; implemented in `41c71fe` with unit tests using an injected render. `EnrichResult` gained `noData`.
- One-off, not in git: the three ledger entries from the first run were relabelled `no_data` in the gitignored cache file so they are not retried. The cache was never committed.
