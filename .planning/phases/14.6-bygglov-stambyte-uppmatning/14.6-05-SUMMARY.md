## What the sweep found

The city lists a stambyte only when someone reported it, so these are recorded cases, not a count of every stambyte that happened.

- 88 searches (11 stadsdelar x 4 search words x 2 start-date windows) returned 2 928 cases in 2 274 buildings. 1 613 cases (1 446 buildings) are stambyten. Relining is 2 cases, both in Norrmalm, so relining is a negligible record in this register.
- The four districts the sold flats sit in, stambyte cases by the decade the case started:

| Stadsdel | 1980s | 1990s | 2000s | 2010s | 2020s | Total (buildings) |
|---|---|---|---|---|---|---|
| Södermalm | 14 | 171 | 162 | 59 | 23 | 429 (383) |
| Kungsholmen | 17 | 97 | 81 | 20 | 14 | 229 (208) |
| Vasastaden | 18 | 132 | 129 | 69 | 14 | 362 (318) |
| Östermalm | 19 | 86 | 118 | 40 | 12 | 275 (245) |

- The record thins out after 2011, as RESEARCH 5.2 expected. Over all 11 stadsdelar 867 stambyte cases started in 1994 to 2006 (about 67 a year) and 144 in 2012 to 2019 (18 a year). That says the city has few reports from those years. It does not say few buildings got new pipes. A building with no case in the list is unknown, not "never had a stambyte". The probable reason is that many associations did not report before the ruling MÖD 2020:19, but the sweep cannot decide that.
- Of the 2 127 cases found by the search word "stam", 1 613 are stambyte cases by our classifier. The other 514 contain the letters "stam" in some other kind of case; they stay in the cache and are not counted as stambyte.
- No answer reached 500 rows (the largest was 442: Södermalm, "stam", 1985 to 2009), every page's own count matched its rows, so no window was split. The splitting code is tested but was not needed live.

## Accomplishments

- A resumable sweep: 88 queries, cached per query, 3 s between requests, one attempt each, run lock held, 24 hour stop on any refusal. A second run over the same cache made 0 requests.
- `stambyte-join.ts`: the sweep plan and window splitting, the runner, the case index (every address of a case, split lists and ranges included, plus every fastighetsbeteckning), the four address classes, and `stambyteAtSale`, which counts years from the sale date and never lets a case after the sale look like a past stambyte.
- Evidence with counts only, written through a strict schema, plus a plain Swedish summary that says what the thin record means.

## Deviations from Plan

**1. [Rule 1 - Bug risk] `sweepWindows()` takes no date**
- **Found during:** Task 1
- **Issue:** The plan names `sweepWindows(runDate)` with the second window ending on the run date. A file name that holds the run date changes every day, so a sweep stopped before midnight would ask all of window 2 again.
- **Fix:** The second window is `{ from: "2010-01-01", to: null }` and no `CaseStartDateTo` is sent, which the city reads as "up to today". `splitWindow` takes `today` only to count the years of an open window.
- **Files modified:** src/lib/discovery/stambyte-join.ts
- **Committed in:** 94f7239, 1c75ff9

**2. [Rule 2 - Missing critical] A state file for splits, requests and timing**
- **Found during:** Task 2
- **Issue:** The sweep cache schema is strict and has no place for "this query was split". Without a record a resumed run would ask the oversized window whole again, and the evidence could not report the request count or the seconds per request across runs.
- **Fix:** `scripts/bygglov-sweep.ts` keeps `sweep-state.json` beside the cache (strict schema, written after every request, damaged file reported and restarted).
- **Committed in:** 1c75ff9

**3. [Rule 3 - Blocking] The evidence writer is not in any task's file list**
- **Found during:** Task 3
- **Issue:** Task 3 lists only the two evidence files as its output, but the script has to produce them, and the strict count-only schema is a threat-model mitigation (T-14.6-42).
- **Fix:** `buildSweepEvidence`, `sweepEvidenceSchema` and `renderSweepMarkdown` in stambyte-join.ts with tests, committed before the live run.
- **Committed in:** 59200ff

**4. [Rule 1 - Bug] Monday window looked at the wrong moment**
- **Found during:** Task 2 (the mid-run test)
- **Issue:** The window check runs before the city client's 3 s start gate, so a request could start up to 3 s inside Monday 06:30.
- **Fix:** The check is made for "now plus 3 s"; the test pins that requests starting at 06:29:50, :53, :56 and :59 run and the one at 06:30:02 does not.
- **Committed in:** 1c75ff9

**5. [Rule 1 - Bug] An assumption was written as a fact**
- **Found during:** Task 3 (reading sweep.md)
- **Issue:** The summary text said many associations did not report before MÖD 2020:19. RESEARCH marks that as an inference.
- **Fix:** The sentence now says "troligen" and that the sweep cannot decide it. sweep.md was regenerated from the cache with 0 new requests.
- **Committed in:** 566e1bd (code) and 175a95d (evidence)

**6. [Process] One extra live request before the sweep**
- A single search (Hjorthagen, "relin", 2025) into a throw-away cache folder checked the live path and the empty-result page (heading count 0) before the 88 real queries. It is not in the evidence totals. 89 requests were made to the city in this plan.
