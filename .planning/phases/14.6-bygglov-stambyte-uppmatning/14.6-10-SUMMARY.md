## Accomplishments

- **Stambyte** reads the completed year, "pågår", "planerat 2027" / "planerat", "genomfört" (done, year unknown) or "okänd". The tracked-flat block adds where it came from (stad, årsredovisning or mäklartext).
- **Byggärenden** leads with the two balcony facts: "Balkonger beviljade 2026-03, ej slutbesked" and "Inglasning ansökt 2026-09". Other recent cases follow as "vind 2023-10", at most three in all. If the city's decision on a balcony case was never read it says "(beslut okänt)". Stambyte and relining cases are never shown here.
- **Area** says where the broker says the figure comes from. For a figure that is not a measurement in a building from before 1987 it appends the separately computed upside, for example "föreningen (+105 571–211 143 kr, antagande)": one and two extra square metres at the flat's own price per square metre. The tracked block prints the soft sentence "Arean bygger på föreningens uppgift, inte en uppmätning." and the note "Kan vara större vid uppmätning (ofta 1–3 kvm, ej säkert)". The upside is not in the profit, the taste, the flags or the order.
- **No number moves.** A test runs the Folkungagatan 61 row with and without every new fact, under the synthetic model and the committed model, and compares profit, taste, resale, purchase, overbid, flags, imputed list and rank. With a test model whose stambyte term is kept, a flat whose building had its stambyte 20 years ago is priced exactly 1,2 % higher (that bucket's value), a building with no stambyte on record gets the reference group's value, and a building whose city list was never read gets no change and is listed as imputed. The committed model has no term, so nothing moves in production.
- **Mail**: the three columns sit after Takhöjd at the same index as the table, the Booli link is still last, and a "<script>" in a Stambyte cell is escaped.
- **Live run**: after the enrichment, the city stage runs over the candidates that got a facts record. It reads the cache first, asks the city only for what is missing, takes the city lock and uses Min Karta only while it is not blocked. If anything fails, one fixed line is logged and the run goes on with the facts the enrichment made. `--no-city` (or `--city-cache none`) skips it. `--area-audit` prints masked area clauses of the first 60 descriptions to the terminal and writes nothing.
- **Coverage**: "Areakälla: angiven i <a> av <n> lästa beskrivningar (uppmätt, föreningen, ekonomisk plan, lägenhetsregistret, säljaren, ej kontrollmätt)" prints after the Takhöjd line when at least one description was read. It does not print for any stored snapshot.
- **Dry run** prints "Stadens e-tjänst: fri" (or "pausad till <tid> (<skäl>)") and "Stadens cache: <n> fastigheter" from files only; on this Mac: fri, 12 fastigheter.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] A refused or withdrawn case is labelled**
- **Found during:** Task 2
- **Issue:** The plan words every case as "<kind> YYYY-MM". A refused balcony would then read "balkong 2025-04", which a reader takes for a built balcony.
- **Fix:** Cases whose decision is avslag or avskrivet get " (avslag)" or " (avskrivet)". Every format the plan fixed is unchanged.
- **Files modified:** `src/lib/discovery/fit-pipeline.ts`, test in `fit-pipeline.test.ts`
- **Committed in:** `a4d6713`

**2. [Rule 2 - Missing critical] The live stage takes the city lock**
- **Found during:** Task 3
- **Issue:** The plan did not mention the lock that `scripts/bygglov-candidates.ts` takes. Without it a manual candidates run and the weekly job could both talk to the city at once and break the 3-second spacing between requests.
- **Fix:** The live hook takes the same lock; when it is taken the stage reads the cache only and prints a line saying so.
- **Files modified:** `scripts/fit-score.ts`
- **Committed in:** `f525bc6`

### Plan wording not followed literally

- **Where the fields are copied.** The plan says the new facts are copied "in both places the ceiling fields are copied". In the code the copy happens once, in the shared `base` object that both the comparable and the not-comparable result use; a test covers both branches.
- **What "read" means for Areakälla.** See key-decisions: counted from the 14.6 text readers' own marks, not `descriptionRead`.
- **A text with no area clause under `--area-audit`.** It counts among the first 60 and prints "Areagranskning <i>: okänd | (ingen areamening)", so a missed clause is visible instead of silent.
- **A pre-existing wording gap, left as the plan wrote it:** the note says "ofta 1–3 kvm" while the kr upside is computed for one and two square metres. Daniel may want one of the two changed.
- **Wave-end fast-forward of `main` and `git push origin main` (plan verification) was not done**, as in plans 08 and 09: a push starts CI and the E2E run on Daniel's Mac. `main` is currently an ancestor of the branch (3 commits ahead), so the fast-forward is clean when it is wanted.
