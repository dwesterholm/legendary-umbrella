# Phase 14.6 Plan 02: The polite door to the city e-service Summary

**One gated client for etjanster.stockholm.se: plain GETs one at a time at least 3 s apart (makeStartGate(3000)), an honest User-Agent, no redirects and no cookies, one attempt, 5 MiB cap, a 24 h per-host stop written to a gitignored block file on any 403/429/login/terms/changed page, and 30-day strict caches for case lists, the address map and sweeps.**

## Accomplishments

### The request rules as implemented

- Every request is a plain GET to `etjanster.stockholm.se` only. The host is a constant; no URL is ever read from a page. A case-list URL looks like `https://etjanster.stockholm.se/byggochplantjansten/arendeochhandlingar?ExtendedAddress=false&RealEstateName=Droskh%C3%A4sten%208`.
- Headers: `User-Agent: bostadai-bygglov/1.0 (personal research; cached, 1 request per 3 s)` and `Accept: text/html`. No Cookie header is sent and Set-Cookie is never read. `redirect: "error"`, so a redirect (for example to a login page) becomes a network failure and ends the run.
- One request at a time. A new request starts at least 3 000 ms after the previous one to the same host (`makeStartGate(3000)`, one gate per host, imported from the frozen Booli file and not edited).
- One attempt. There is no retry anywhere.
- An answer is accepted only with HTTP 200, a content-type that contains "html", and at most 5 MiB (length declared up front and counted while streaming). A timeout of 30 s aborts the request.
- Extended searches use the names the browser script itself uses: `District`, `Description`, `CaseStartDateFrom`, `CaseStartDateTo`. The `SearchParameters.` prefix is never built (the city returns the empty form for it).
- Order inside every public call: check the block file, check the request budget, wait for the 3 s gate, make the one fetch.
- Logs carry host, path without query, status, kB and seconds, or a fixed label, always starting with `[stockholm] `. A test feeds a secret body text and a Set-Cookie header and checks neither appears.

### What trips the gate, and for how long

| What happened | Label | Host blocked? | Run stops? |
|---|---|---|---|
| HTTP 403 | `http-403` | yes, 24 h | yes |
| HTTP 429 | `http-429` | yes, 24 h | yes |
| Page is a login form (BankID, "Logga in") | `inloggning` | yes, 24 h | yes |
| Page is a terms page (Användarvillkor) | `villkor` | yes, 24 h | yes |
| Page shape changed (marker gone, rows do not fit, count differs on a beteckning list) | `andrad-sida` | yes, 24 h | yes |
| 200 answer that is not HTML | `fel-innehallstyp` | yes, 24 h | yes |
| Body over 5 MiB | `storlek` | no | `caseList`: yes. `extendedSearch` returns `{ ok: false, reason: "storlek" }` so the caller splits the window |
| Extended search whose own count differs from its rows | `antal` | no | returned to the caller to split |
| Fetch rejects (network, timeout, refused redirect) | `natverksfel` | no | yes |
| Any other HTTP status (404, 500, ...) | `http-<status>` | no | yes |
| Request budget used up (default 400, settable) | `budget` | no | yes |
| Host already blocked | `pausad` | n/a | yes, no request made, log says "Stadens e-tjänst pausad till <iso> (<label>)" |

The block lives in `.planning/calibration/data/host-gates.json` as `{ "<host>": { blockedUntil, reason, disabled? } }`. It ends exactly 24 h after the refusal (`blockedUntil` equal to the refusal time is already free). `disabled: true` means blocked with no end (plan 04 uses it if Min Karta refuses the honest User-Agent). A damaged block file is reported in Swedish and counts as no block when read; `blockHost` says it is rewriting it before it does.

### Cache TTL and refetch rules

- A case list is fresh at 29 d 23 h and stale at exactly 30 d. A `fetchedAt` more than 1 day in the future, an unparsable time, or a `rulesVersion` different from `BYGGLOV_RULES_VERSION` is stale.
- A missing file is silent. A stale, wrong-version, invalid-JSON, wrong-format or other-fastighet file is a miss said out loud (`[stockholm] cache droskhasten-8: <reason>, hämtas på nytt`); the file is never renamed or deleted, the fresh answer overwrites it.
- Address map (`address-beteckning.json`): key is the normalised address ("Torsgatan 48 A" gives "torsgatan 48a"); a resolved entry is fresh for 365 d, an ambiguous or empty one for 30 d; `fetch_failed` is refused by `saveAddressMap`.
- Sweep files `sweep/<stadsdel>-<sökord>-<från>-<till|open>.json` use the same 30 d / rulesVersion rule (`sweepNeedsRefresh`).
- Files hold tags, digits and dates only. The schemas are strict, so a Description, Handler or Documents key cannot be saved and a hand-edited file carrying one is a "fel format" miss.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] URLSearchParams cannot produce the URL the plan expects**
- **Found during:** Task 1
- **Issue:** The plan says URLs are built "with URL and URLSearchParams", but its expected URL has `Droskh%C3%A4sten%208`. URLSearchParams writes a space as `+`.
- **Fix:** the fixed host goes through `new URL`, the query is written as `key=encodeURIComponent(value)` pairs.
- **Files modified:** src/lib/stockholm/bygglov-client.ts
- **Verification:** the tracer test pins the exact URL; the extended-search test pins `S%C3%B6dermalm`
- **Committed in:** 1e12d2c

**2. [Rule 2 - Missing critical] Cold and warm answers had to match, so the "other" cases are cached too**
- **Found during:** Task 1
- **Issue:** `caseList` returns `otherCases` (used for hiss) but the plan's cache entry shape had only `cases`; a cache hit would silently drop them.
- **Fix:** the entry has an `otherCases` array (default empty).
- **Files modified:** src/lib/stockholm/bygglov-cache.ts
- **Committed in:** 1e12d2c

**3. [Rule 2 - Missing critical] Statuses and parse failures the plan did not name**
- **Found during:** Task 2
- **Issue:** the plan names 403/429/login/terms/shape but not what an HTTP 500, a 404, or a heading-count mismatch means.
- **Fix:** other statuses stop the run without blocking (`http-<status>`); `count` on a beteckning list is treated as a changed page and blocks; `count` on an extended search returns `antal` so the sweep can split the window (RESEARCH 5.1).
- **Files modified:** src/lib/stockholm/bygglov-client.ts
- **Committed in:** 2520620

**4. [Rule 2 - Missing critical] A default request budget**
- **Found during:** Task 2
- **Issue:** T-14.6-10 lists a request budget as a mitigation, but the plan gave no default; with none, a bug in a caller could loop against the city all night.
- **Fix:** `CITY_LIMITS.maxRequestsPerRun = 400`, overridable with `budget`. Plan 04's sweep (88 searches plus details) fits; a caller that needs more passes a larger number on purpose.
- **Committed in:** 2520620

**5. [Rule 1 - Bug] A long address list could have failed a whole sweep save**
- **Found during:** Task 3
- **Issue:** the list parser does not bound the number or length of addresses per row, the strict sweep schema does.
- **Fix:** the client keeps at most 20 addresses of 80 characters per sweep case; the sweep case's `beteckning` may be empty so a case the city lists without a fastighet cannot break a file.
- **Files modified:** src/lib/stockholm/bygglov-client.ts, src/lib/stockholm/bygglov-cache.ts
- **Committed in:** 0bdcace
