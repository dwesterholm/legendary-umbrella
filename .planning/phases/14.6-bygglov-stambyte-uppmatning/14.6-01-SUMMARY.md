# Phase 14.6 Plan 01: City case pages parsed into name-free cases and building facts Summary

**Pure parsers read Stockholm's embedded case JSON (list page, detail page, address fragment) with typed failures, a tag-set classifier with tillsyn and balcony-renovation guards turns 556 real ärendemeningar into kinds, and `buildingFactsOf` gives Folkungagatan 61's building stambyte 2006 and no balcony flag, with no officer name or free text kept anywhere.**

- The list page parses from `CaseSearchResultsViewModel`. Droskhästen 8 gives 53 build cases and 27 other cases, every row exact-matched on "Droskhästen 8". - Folkungagatan 61's building, from the list alone: last stambyte 2006 (basis "start"), no stambyte under way, no balcony flag, short list vind_inredning 2023-10 then hiss 2021-12.

### What the parser extracts from each page type

| Page | What comes out | What is dropped |
|------|----------------|-----------------|
| List page (beteckning search or extended search) | per row: rec (digits), case type, start date, beteckning, street addresses (split on `,` and `\,`), diarienummer, archived flag; the free sentence only in memory for the classifier; the build-list count; texts of any "villkor" links | everything else on the page |
| Detail page | rec (null for archived), diarienummer, start and closing date, estates, every decision as date + type + code | Handler, the Handläggare line, Documents, Group, Definition (free text) |
| Address fragment | list of {text, value} where value is the fastighetsbeteckning; the empty "Välj fastighet" placeholder is dropped and entities are decoded; null when there is no select list | |
| Any page with no view model | `login` (words like "Logga in", BankID, e-legitimation in a form or the main heading), `terms` (Användarvillkor), else `shape` | |

### Tag rules and what they produce on the 556 real cases

A case gets a set of kinds, a primary kind (priority: relining, stambyte, balkong_inglasning, balkong_ny, balkongdorr, balkong_renovering, hiss, vind_inredning, fasad, tak, annat) and a separate tillsyn flag. The counts below are pinned in the test as a regression guard. They are not a precision measure: the samples were picked by keyword (the stambyte and balcony sweeps) plus all of Droskhästen 8.

| Kind | Cases carrying the tag | Cases where it is the primary kind |
|------|-----------------------|------------------------------------|
| stambyte | 380 | 380 |
| balkong_ny | 59 | 59 |
| balkong_inglasning | 25 | 25 |
| balkongdorr | 33 | 4 |
| balkong_renovering | 14 | 12 |
| hiss | 22 | 9 |
| vind_inredning | 24 | 5 |
| fasad | 42 | 4 |
| tak | 6 | 1 |
| relining | 0 | 0 |
| annat | 57 | 57 |

12 of the 556 are tillsyn (an enforcement text at the start, or the word "olovlig..." anywhere). The first-pass numbers in RESEARCH 4.1 (balkong_ny 59, balkong_inglasning 25, annat 59 and so on) are matched or close; balkong_renovering and hiss differ because the tag set now counts co-tags and the table was tightened.

Eyeball pass (10 distinct rows per kind, then every row that mentions balkong, vind, glas or stam without the matching tag): two real misses found and fixed ("Uppförande av balkongrader" and "Inredning av råvind"). Remaining known edges, none changed on purpose:
- "Särskild besiktning av lintrummehissar" (an OVK inspection row from the other-cases list) is tagged hiss; it is an inspection, not a lift installation.
- "balkonger på fasad" inside a stambyte text tags fasad as well; harmless.
- "utrymningsbalkonger", "nödbalkonger" and "vädringsbalkong" are deliberately not new balconies.
- A text like "Nybyggnad av flerbostadshus med balkonger" would tag balkong_ny. It does not occur in the saved data.

### Building facts, in words

- `lastStambyteYear`: the latest slutbesked year among stambyte cases, else the start year of the latest stambyte case that started more than 3 years ago, and basis says which. Relining never sets it. Cases closed as Avskrivet or Avslag count for nothing.
- `stambyteOngoing`: a stambyte started in the last 5 years with a granted startbesked, no slutbesked, not closed. Null if a recent stambyte case has not had its decisions read.
- `balkongBeviljadEjByggd`: a new or glazed balcony (no tillsyn) started in the last 5 years, granted (Startbesked or Lov), no slutbesked, not closed as Avskrivet/Avslag. Renovation and balcony doors alone never set it. Null if a qualifying case was not read.
- `balkongInglasningAnsokt`: a glazing case in the last 5 years with no grant, no closing and no refusal.
- A case that starts after the run date is ignored everywhere.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan's diarienummer character set would reject a real row**
- **Found during:** Task 1 (scan of the three real list pages)
- **Issue:** One real row has the diarienummer `IV:2170/69`. Refusing a row for the colon would fail the whole parse as `shape`.
- **Fix:** characters outside `[0-9A-Za-z/ -]` are dropped and the result is cut to 20 characters, so the stored value is `IV2170/69`. The T-14.6-04 goal (no injection through a stored string) holds either way.
- **Files modified:** src/lib/stockholm/bygglov-parse.ts
- **Verification:** sweep test checks every diarie of all four row sets against the allowed pattern
- **Committed in:** ca2419c

**2. [Rule 1 - Bug] Archived detail pages have no RecNo and no Estates**
- **Found during:** Task 2 (the 2006 fixture failed the first schema)
- **Issue:** the 2006 case has `RecNo: null` and `Estates: []` (the beteckning sits in `RealEstatesNames`).
- **Fix:** `CaseDetail.rec` is `string | null`; `applyDetail` refuses a detail whose rec is set and differs from the stored case, and accepts null.
- **Files modified:** bygglov-parse.ts, bygglov-parse.test.ts
- **Committed in:** fbfb95f

**3. [Rule 3 - Blocking] The sweep pages have no "Visar 1-50 av N" heading**
- **Found during:** Task 1
- **Issue:** the plan says the sweeps must give `headingCount` equal to the row count, but only the Droskhästen page has the "Visar" heading; the sweeps show "Byggärenden (380 träffar)" in the tab.
- **Fix:** both forms are read; each present one must equal the array length, and `headingCount` is the "Visar" number when present, else the tab number.
- **Committed in:** ca2419c

**4. [Rule 2 - Missing critical] Rule refinements the eyeball pass called for**
- `balkong_ny` accepts the balcony noun only ("balkonger", "balkongrader", "påhängsbalkong"), so "montering av balkongräcke" is not a new balcony.
- `takterrass` counts as vind_inredning only after a building verb ("uppförande av takterrass"), so "Renovering av takterasser" does not.
- `fasad` excludes "fasadskylt"/"fasadreklam".
- "råvind" and "balkongrader" added after two real misses.
- Enforcement (tillsyn) cases are excluded from stambyte facts, the short list and `needsDetail`; the plan did not say either way and a complaint is not a recorded work.
- `decisionKind` was written in Task 1 instead of Task 3 because `buildingFactsOf` needs it to count unknown decision types.
- **Committed in:** ca2419c, 7421d91
