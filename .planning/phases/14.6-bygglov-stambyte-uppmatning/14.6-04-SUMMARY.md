**2. [Rule 2 - Missing critical] A redirect must not pass for a network error**
- **Found during:** Task 1
- **Issue:** The client sends `redirect: "error"`, so a redirect to a login page surfaces as `natverksfel` and does not block the host (the blind spot noted in plan 02). The plan's verdict rule did not cover it.
- **Fix:** The runner counts fetch errors that are refused redirects; one redirect gives STOPP "omdirigering" and ends the run.
- **Files modified:** scripts/bygglov-spike.ts, src/lib/stockholm/spike-report.ts
- **Committed in:** 1982d50

**3. [Rule 2 - Missing critical] A GO that shows nothing is not a GO**
- **Found during:** Task 1
- **Issue:** A run where every lookup failed (for example HTTP 500 on all of them) would still have carried verdict go.
- **Fix:** STOPP "for-fa-byggnader" when fewer than 10 buildings (or fewer than asked, for `--only`) were tried, and "ingen-losning" when none resolved.
- **Files modified:** src/lib/stockholm/spike-report.ts, spike-report.test.ts
- **Committed in:** 1982d50

**4. [Rule 2 - Missing critical] The dry run must fail when it asks for a page that is not saved**
- **Found during:** Task 1
- **Issue:** The fixture fetch answers an unrouted URL with 404 and the client treats that as an ordinary failure, so the dry run could pass while a real request would have gone out.
- **Fix:** The dry run records every 404 from the saved pages and exits 1 if any occurred. Checked with `--only 130457`, which has no saved list: exit 1.
- **Files modified:** scripts/bygglov-spike.ts
- **Committed in:** 1982d50

**5. [Rule 3 - Blocking] The dry run needs the client module**

Offline is guaranteed instead by the injected fixture fetch, a global `fetch` replaced by a function that throws, a throw-away cache and block list, and the 404 check above. The Min Karta resolver is never used in a dry run.
- **Files modified:** scripts/bygglov-spike.ts
- **Committed in:** 1982d50
