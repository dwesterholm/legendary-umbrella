# Phase 14.6 Plan 03: Address to fastighetsbeteckning in four rungs Summary

**resolveBeteckning finds the building behind an address through four rungs (broker text, BRF name confirmed by the city's own rows, the city's address search, Lantmäteriet Min Karta ported from the rental repo), each accepting only an exact match, with every answer cached per address and unknown left as unknown.**

## Performance

- **Duration:** about 11 min
- **Started:** about 2026-10-18T17:06Z
- **Completed:** 2026-10-18T17:17Z
- **Tasks:** 3 (task 1 was the tracer)
- **Files:** 9 created, 1 modified (`bygglov-client.ts`, 9 added lines)
- **Network requests:** 0. Every test uses saved pages and saved Min Karta answers through the injected fetch. No Booli, no Anthropic. `.planning/calibration/data/` was not written to and `slutpriser-cache.json` was not touched.

## Accomplishments

### The four rungs and what each accepts

| Rung | Source | Accepted only when | Cost |
|---|---|---|---|
| a | Broker text containing "fastighetsbeteckning" | The word is followed by a designation that starts with a capital letter and ends in a number ("Stockholm Oljan 29" gives "Oljan 29"). Street land is refused. | none |
| a2 | BRF name such as "BRF Oljan 18", read as the guess "Oljan 18" | The city's case list for that guess has a row whose address is the candidate's own street and number (entrance letter ignored, "Östgötagatan 33/Folkungagatan 61" read as two addresses). If it fails the guess is dropped and rung b runs. On success the already fetched list is handed back to the caller and also saved to the case-list cache. | one GET, reused when it works |
| b | The city's own AddressSearch | Options whose address EQUALS the asked one all name one designation. "Hornsgatan 42" accepts 42A and 42B; "Hornsgatan 42A" only 42A; "Hornsgatan 4" is no match for 42A/42B; two different designations give ambiguous. | one GET |
| c | Lantmäteriet Min Karta | A search hit in Stockholm kommun with the same address, then the first buffer (0, 5, 10 m) that returns plots: one plot is the answer, several are tested by point-in-polygon and the first plot whose boundary contains the address point wins. Plots in another kommun are dropped. | 2 to 5 GETs |

The first rung that answers wins. Whatever happens is remembered in `address-beteckning.json`: resolved for 365 days, ambiguous or empty for 30 days. A city stop, a refused request or a failed lookup stores nothing.

### Min Karta rules as implemented

- Requests go only to `minkarta.lantmateriet.se`, built from the fixed host plus the cleaned address, numbers read from the search answer and an object id that must look like a UUID.
- Headers: `User-Agent: bostadai-bygglov/1.0 (personal research; address to fastighetsbeteckning, 1 request per 3 s)`, `Referer: https://minkarta.lantmateriet.se/`, `Accept: application/json`. No cookie. `redirect: "error"`. The rental repo's browser User-Agent string is not copied (a static grep on the file is clean).
- Its own pacer (a separate `makeHostPacer`), so request starts are at least 3 000 ms apart across all addresses of a run and never wait behind the city's pacer.
- One attempt, no retry. At most 5 calls per address.
- A 403 or 429, or a 200 that is not JSON, puts only `minkarta.lantmateriet.se` on the 24 h list (`http-403`, `http-429`, `fel-innehallstyp`), ends the lookup as `fetch_failed` and is not cached. Any other failure (network, 500, bad JSON) is `fetch_failed` without a block. A host entry with `disabled: true` (written by plan 04's spike if the honest User-Agent is refused) means no request at all.
- Logs carry host, path without query, status, kB and seconds, always starting with `[stockholm] `; the query, point and transaction id never appear.

## Decisions Made

See `key-decisions`. Two deserve plain words:

- **Why Min Karta stops at the first containing plot.** The rental repo asks for the boundary of every candidate and wants exactly one to contain the point. Here one address may cost 5 calls (search, three buffer steps, one more), so after a 10 m buffer only one boundary fits in the budget. Plots are tried building-first and street land last. A point lies inside one property, so the first plot that contains it is the answer; if the budget runs out before one does, the address is ambiguous and stays okänd.
- **Why a failed Min Karta call stores nothing even when the other rungs said "nothing".** Two rungs finding nothing is only a safe "nobody knows" if the third rung was also asked. Storing it would hide the address for 30 days behind an outage.

- **Fix:** `CaseListAnswer` got `addresses: string[]` (exact-match rows' addresses, deduplicated, each cut at 80 characters, at most 40). It is in memory only; the case-list cache schema is unchanged.

- **Verification:** the whole stockholm folder (241 tests) and the full suite (3442) pass; the real Droskhästen 8 fixture confirms Folkungagatan 61 and rejects Folkungagatan 63
- **Committed in:** a930447

**2. [Rule 1 - Bug] The research regex for rung (a) accepted lower-case junk**
- **Found during:** Task 2
- **Issue:** RESEARCH 3.3 uses the `i` flag on the whole pattern, so its capital-letter class also matches lower case: "Fastighetsbeteckning är Oljan 29" would capture "är Oljan 29" and rung (a) accepts without any request.
- **Fix:** only the keyword ignores case; the designation after it is matched case-sensitively in a 90-character window after each keyword (at most 20 keywords per text), and the result must look like "<words> <number>[:<number>]". "Fastighetsbeteckning: Stockholm 2012" gives null, not "2012".
- **Files modified:** src/lib/stockholm/beteckning-text.ts
- **Verification:** tests for "är Oljan 29", "Stockholm 2012" and four 50 000-character texts built to be slow (all under 50 ms)
- **Committed in:** 5a1f92c, a930447

**3. [Rule 2 - Missing critical] A neighbour kommun's plot could have been mapped to a Stockholm designation**
- **Found during:** Task 3
- **Issue:** a 10 m buffer near the border can return "SOLNA OLJAN 29"; dropping the kommun would make it "Oljan 29", a Stockholm building. T-14.6-20 (the wrong building shown as this flat's).
- **Fix:** candidates whose designation does not start with "STOCKHOLM " are dropped before anything else; a test shows "SOLNA OLJAN 29" ends as no_candidates.
- **Files modified:** src/lib/stockholm/minkarta.ts
- **Committed in:** 060c1bf

**4. [Rule 2 - Missing critical] A non-JSON 200 from Min Karta is a refusal**
- **Found during:** Task 3
- **Issue:** the plan names 403 only. An HTML page where JSON is expected is how a challenge page looks, and the city client already treats the same case as a refusal.
- **Fix:** a 200 without a JSON content type blocks the host 24 h (label `fel-innehallstyp`) and returns fetch_failed.
- **Files modified:** src/lib/stockholm/minkarta.ts
- **Committed in:** 060c1bf

**5. [Rule 1 - Bug] The plan's call budget and its example cannot both hold**
- **Found during:** Task 3
- **Issue:** the behavior block says "at most 5 calls per address" and also walks buffer 0, 5, 10 (three calls) plus the search and then the boundary of each of four candidates (four calls): 8 calls.
- **Fix:** the budget of 5 is kept (it is the politeness rule). Candidates are tried building-first, street land last, and the first containing plot wins; with the Bondegatan 59 fixtures that is call number 5. Street land is never fetched when a building plot contains the point, so the street-land fixture is exercised by the point-in-polygon unit tests (and by a flow where it is the only candidate), not by the main flow.
- **Files modified:** src/lib/stockholm/minkarta.ts, minkarta.test.ts
- **Committed in:** 060c1bf

**6. [Rule 1 - Bug] Plan said the street-land point sits "in a hole or outside"**
- **Found during:** Task 3
- **Issue:** I first assumed the Bondegatan 59 point was inside the street land's outer ring and held out by a hole. Computed from the fixture: it is outside the outer ring and in no hole, so that point cannot prove the hole rule.
- **Fix:** the test for holes uses the centre of the first of the 15 holes (inside the outer ring alone, outside the full parcel); the Bondegatan 59 point is tested separately as "not contained".
- **Files modified:** src/lib/stockholm/minkarta.test.ts
- **Committed in:** 060c1bf

**7. [Rule 2 - Missing critical] A confirmed BRF-name list is saved to the case-list cache**
- **Found during:** Task 2
- **Issue:** the plan says the list is returned "for reuse (no second list fetch later)". That only holds if the caller keeps it; a caller that goes through the cache would fetch it again.
- **Fix:** on an (a2) success the list is also written with `saveCaseList`, so a later `refreshCaseListIfStale` is a cache hit. The list is also on `result.list`.
- **Files modified:** src/lib/stockholm/beteckning.ts
- **Committed in:** a930447
