# Phase 14.3 Plan 05: Orientation precedence Summary

**One function, `resolveSunFact`, turns whatever is known about a flat's facing direction into a single SunFact: the broker's text beats a floor-plan compass, which beats the building footprint; a disagreement of more than 90 degrees halves the confidence and shows both ("N (angiven, 0,50) konflikt: planritning S"); nothing known stays "okänd" with confidence 0.**

## Accomplishments

- Precedence works end to end in the pure module. The floor-plan branch exists and is tested, but nothing feeds it in production: plan 03 closed the route, so plan 07 will pass `plan: null` while `FLOORPLAN_ROUTE_ENABLED` is false.
- Konflikt is strict: exactly 90,0 degrees is not a conflict, 90,1 is. Distances wrap round north (359,9 against north is 0,1) and are compared at the stored 1-decimal precision.
- A stated facade picks its side of the building. "Väster" on a flat whose street side is 106 degrees takes the courtyard bearing 286 (and 274 for the 94/274 flat), plus the courtyard window point, so plan 04's hours engine can reason about neighbours for it. A stated facade more than 45 degrees from both sides keeps the sector centre and no point (theoretical hours only).
- The footprint evidence (building id, street and courtyard bearings, corner flag, floor-above-levels flag) stays on every fact whose footprint is known, so the evidence report can show the street side of a stated flat.
- `statedFacadesOf` merges the candidate's orientation and the facts record into one list in the order north, east, south, west.
- `formatSolCell` from plan 01 already printed the stated, plan and konflikt shapes exactly; no change was needed. Tests now pin them.
- 56 new tests, `npm run test`: 2 350 passed / 3 skipped (the brief's baseline was 2 294 / 3). `npx tsc --noEmit` and `npm run lint` clean.

## Decisions Made

- The footprint's street and courtyard sides are opposite, so the nearer of the two is at most 90 degrees from any bearing. In practice the footprint can only disagree with stated text or a plan when its sides are not opposite. The code follows the plan's rule literally (nearer side); the conflict tests use synthetic non-opposite footprints to exercise it. Real conflicts will mostly be stated-versus-plan, which only matters once the floor-plan route is open.
- A non-finite plan bearing or confidence drops the plan source instead of storing NaN (which would fail the schema on read-back).
- Stated confidence is 1,00 per R-03. This is a different number from the 0,5 that `extractOrientationFromDescription` returns for `computeSunExposure`; that function is untouched.
