## Accomplishments

- Overpass client: the four-host list (mirrors first, the overloaded main host last), 3 rounds, 3 s between endpoints, 15 s between rounds, one request at a time, `redirect: "error"`, User-Agent and Accept pinned, 200 s timeout per request that also covers the body read.
- Answer validation before anything is saved: HTTP 200, json content-type, declared length and streamed size both capped at 50 MB (a declared 60 MB is rejected without reading the body, a streamed one stops reading at the cap), JSON parse, at most 200 000 elements, bounded zod schema (lat/lon ranges, at most 10 000 points per way, at most 5 000 members), no `remark` with "error", at least 5 000 building ways and 1 000 road ways.
- Cache rules: the age rule at 31 days inclusive, fail-closed load with four error words, guarded compact atomic save, and a refresh decision that returns one of four actions with the four pinned lines.
- CLI `scripts/osm-download.ts` with `--force`, `--path` (guarded), `--import-research <dir>`, `--help`; exit 1 on a failed download with the old file untouched.
- 64 new tests (33 for the client, 31 for the cache). Mutation spot checks: changing `>=` to `>` in the age rule fails 2 tests; changing `redirect: "error"` to `"follow"` fails 1.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking/Consistency] Import from plan 01 instead of duplicating its constants**
- **Found during:** Task 1
- **Issue:** The plan says "Do not import plan 01's modules (same wave)". Plan 01 is merged on this branch, and writing the ODbL attribution string and the two geometry caps a second time would let the two copies drift (plan 01's schema refuses a file whose attribution does not mention "OpenStreetMap contributors").
- **Fix:** `osm-overpass.ts` imports `OSM_ATTRIBUTION`, `OSM_MAX_POINTS_PER_WAY`, `OSM_MAX_MEMBERS_PER_RELATION` and the `OsmExtract` type from `osm-buildings.ts`; `osm-cache.ts` re-exports `OSM_ATTRIBUTION`. A test pins that `OVERPASS_LIMITS` equals the schema's caps. The parser's turf dependency is loaded in the script as a side effect, which is harmless.
- **Files modified:** `src/lib/discovery/osm-overpass.ts`, `src/lib/discovery/osm-cache.ts`
- **Commit:** `3ac7cf4`

**2. [Rule 2 - Missing critical] Bad save path found before the download, not after**
- **Found during:** Task 1
- **Issue:** The plan guards the path inside `saveOsmCache`, which runs after the download. A bad `--path` would cost a full download and then fail.
- **Fix:** `refreshOsmCacheIfStale` and the CLI check `guardedDataPath` first; a bad path returns a failed action (or exits 1) without a request. Tested: the download spy is not called.
- **Commit:** `3ac7cf4`, `2960085`

### Additions beyond the plan text

- A fourth load error word `oläsbar` (the file exists but cannot be read as a file, for example a directory or no permission), because `loadOsmCacheRaw` must never throw and the three listed words did not cover it.
- `saveOsmCache` and `refreshOsmCacheIfStale` take an optional `dir` (tests use a temp directory, the same device `saveVisionCache` has), so no test touches the real cache.
- A 3 s pause between the three queries (the plan's "at most 1 request per second" holds on the happy path too).
- The evidence log also carries the rerun with fetch disabled, which the plan did not ask for. The preload script used for it lived in the session scratch directory and is not committed.

**Total deviations:** 2 auto-fixed (1 consistency, 1 missing critical), 4 small additions. **Impact:** no scope change; the cache file is smaller than the plan estimated because `bounds` is not stored.
