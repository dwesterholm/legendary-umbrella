### `src/lib/discovery/sun-hours.ts` (pure, suncalc)

**Analog:** `src/lib/discovery/sun-path.ts`

**Imports and file-level doc discipline** (lines 1-38): `import * as SunCalc from "suncalc";` then a block comment stating PURE, no I/O, "NEVER imported by `niche-score.ts` or `flags.ts`", and the azimuth convention (degrees, north-zero, clockwise; 0=N, 90=E, 180=S). Copy that structure and add the new assumptions (floor base, +-3 m envelope, 3 m per storey).

**How suncalc is called** (lines 114-127):
```typescript
const baseDate = new Date(SEASON_REFERENCE_DATES[season]);
...
const pos = SunCalc.getPosition(sampleDate, latitude, longitude);
if (pos.altitude <= 0) continue; // below horizon
if (angularDistance(pos.azimuth, center) <= 90) { ... }
```
Note: suncalc 2.0.0 returns DEGREES (azimuth and altitude), so `Math.tan(altitude * Math.PI / 180)` is needed for `tanAlt`. Reuse the `angularDistance` helper idea (lines 97-100); it is not exported, so copy it (do NOT edit `sun-path.ts`; `computeSunExposure` must stay byte-identical, RESEARCH Probe 4).

**Signature to reuse** (lines 198-203, do not change):
```typescript
export function computeSunExposure(
  latitude: number | null, longitude: number | null, floor: number | null, orientation: Facade[] | null,
): SunExposureResult
```
`floor` is accepted but unused today. New hours engine is a separate function. Import types with `import type { Facade } from "@/lib/discovery/sun-path";` (as `taste.ts` line 33 does).

**Null sentinel rule** (doc lines 22-27): unknown returns `null`, never zero. Carry this: a flat with no inference returns `null` hours, not 0.

**Local-hour windows:** use `Intl.DateTimeFormat("sv-SE", { timeZone: "Europe/Stockholm", hour: "2-digit", minute: "2-digit", hourCycle: "h23" })` (RESEARCH Code Examples), never `getHours()`. Test with `TZ=America/New_York`.

**Ray-check core:** copy `blocked(...)` from RESEARCH "Ray against wall segments" (any crossing with `h > z + t * tanAlt` blocks). Radius 250 m (RESEARCH measured) although CONTEXT D-06/R-04 says 150 m; use 250 and flag it for the planner.

export function sunScore(orientation: { facades: Facade[] } | null, phrases: SunPhrases | null): number {

## Shared Patterns

### Purity and structural separation
**Source:** `sun-path.ts` lines 1-38, `taste.ts` lines 1-30, `watch-reasons.ts` lines 1-50
**Apply to:** all new pure modules
Doc block states PURE (no clock, randomness, network, file, env), "Same input, same output", every number in one exported table, and "`niche-score.ts` and `report/flags.ts` must NEVER import it; the static-grep invariant in `niche-score.test.ts` enforces that and the specifier is registered there." Local time must come from the injected date, not `Date.now()`.

### Degrade, never guess
**Source:** `sun-path.ts` lines 22-27, 204-206; `watch-reasons.ts` "MISSING IS NOT NO"
**Apply to:** inference, hours, taste, report cells
Unknown is `null` / "okänd" / weight 0 and prints `-`, never `0 timmar`. Every inference carries `source` and `confidence` (D-02).

### Additive nullable-default schema fields
**Source:** `listing-facts.ts` lines 71-122, `fit-score.ts` lines 119-136
**Apply to:** any new field on facts/row/snapshot
`.nullable().default(null)` so old snapshots replay (R-08).

### Atomic, guarded cache I/O
**Source:** `json-store.ts`, `vision-cache.ts` 138-176
**Apply to:** OSM cache, floor-plan cache
`guardedDataPath` then `writeJsonAtomic`; never write outside `.planning/calibration/data/`.

### Coverage-line format
**Source:** `fit-pipeline.ts` line 634
**Apply to:** the new sun coverage items
`${label} ${known} av ${coverage.n} (${percent(known, coverage.n)} %)`, joined with `, ` after `Täckning (N annonser): `.

### Secrets and logging
**Source:** RESEARCH Security Domain, `vision.ts` logging only `{ booliId, code }`
**Apply to:** probe and fetch scripts
Never print the API key, image URLs with results or response bodies.
