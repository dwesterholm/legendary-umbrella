# Phase 14.1 Plan 03: Offline fit-score tracer Summary

**Pure scoring library plus headless `--replay` script: a stored for-sale snapshot goes through a zod-validated hedonic model, a reno bundle priced from RENO_COST_MATRIX and the unchanged `valueGap()` to a ranked, fully decomposed flip-profit table, with no network.**

## Performance

- **Duration:** about 7 min (clock-based, approximate)
- **Completed:** 2026-10-12T19:48:00Z
- **Tasks:** 2 (Task 1 is the tracer, Task 2 locks it with tests)
- **Files:** 10 (7 created, 3 modified)

## Accomplishments

- The shape works end to end. `npx tsx scripts/fit-score.ts --replay <snapshot> --model <model>` ranks the 47 snapshot rows (46 comparable, 1 not) in well under a second and prints the table, a decomposition block for Booli 150148 and the "Ej jämförbar" list.
- Tracer gate (auto mode): after the Task 1 commit the `<verify>` command was re-run and passed ("Tracer verified end-to-end - expanding") before any Task 2 work.
- The model file is untrusted input. Seven kinds of malformed model are rejected with a readable error before any price is computed, including one that would put a candidate outside the fitted size range (R-12 fields `minLivingArea`/`maxLivingArea` are in the schema).
- The unknown reno bundle is derived from `RENO_COST_MATRIX`, not typed in: 105 000 kr (kitchen-cosmetic 45 000 + bathroom-cosmetic 27 500 + paint-apartment 32 500). Fresh totals 10 000 and dated 427 500, as R-01 states.
- The separation guard gained its positive control: the matcher now demonstrably recognises `fit-score.ts` as importing a registered specifier, while `niche-score.ts` and `flags.ts` assertions are untouched and still false.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug, test wording] "Null floor equals floor at the feature mean" cannot hold as worded**
- **Found during:** Task 2 (writing the hedonic-model test)
- **Issue:** The behavior line says a null floor gives the same price as floor = feature mean. The floor mean is 2.5 but `groundOrBelow` for a real floor of 2.5 is 0, while a null floor correctly marginalises it at its own mean (0.1). The two differ by about 1 %, so the sentence is not true of correct code.
- **Fix:** The test zeroes the floor and ground-floor coefficients on a model copy and asserts a null floor then prices identically to a known floor, plus a second test that the real fixture lists `floor` in `imputed`. The code is unchanged.
- **Files modified:** src/lib/discovery/hedonic-model.test.ts
- **Committed in:** bb94d07

**2. [Rule 1 - Bug] Fixture stored `a` values rounded to 6 decimals**
- **Found during:** Task 2 (the planned `toBeCloseTo(0.08, 12)` for Södermalm)
- **Issue:** `a = ln(1.08)` rounded to 0.076961 gives an overbid off by about 5e-7, which fails the planned 12-digit assertion.
- **Fix:** Regenerated the fixture with full-precision `a` and `overallA` (Vasastan stays exactly 0).
- **Files modified:** src/lib/discovery/__fixtures__/hedonic-model.fixture.json
- **Committed in:** bb94d07

**3. [Rule 3 - Blocking] ESLint warning on the unused stub parameter**
- **Found during:** Task 1
- **Issue:** `renoEstimateFromVision(_vision)` raised `no-unused-vars`, and the success criteria want lint clean.
- **Fix:** Named the parameter `vision` and referenced it with `void vision;` plus a comment that 14.1-06 reads it.
- **Committed in:** 07d52c1

### Plan statement that is only partly true

**The replay path "never loads the Booli client" holds for the script's own imports, not transitively.** `fit-score.ts` parses candidates with `discoveryCandidateSchema` (needed for the image-host allowlist, T-14.1-06), and `candidate.ts` imports `isAllowedImageHost` from `@/lib/booli/client`, which imports `./transport` (the Apify client). So the module code is loaded in a replay; nothing is called. What is proven: the script has zero static imports of `@/lib/booli`, the job module or the vision module (acceptance grep returns 0, and a test asserts it), and a stubbed `fetch` is never called while ranking all 47 rows. What is not proven: that no network module is ever loaded. Removing the dependency means moving `isAllowedImageHost` to a pure file, which edits `candidate.ts` and `client.ts` and so touches a prohibited area; I did not do it. Suggest a small follow-up (or fold into 14.1-09, where the live mode arrives).
