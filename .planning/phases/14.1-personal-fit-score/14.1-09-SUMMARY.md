# Phase 14.1 Plan 09: Headless pipeline and live mode Summary

**`runFitPipeline` puts the order of paid calls (scrape four districts, filter, free pre-rank of everything, detail pages and picture reading for the top 20 only, re-rank by profit) into one tested function with injected I/O, and `scripts/fit-score.ts` can now run it live behind an Apify headroom check that stops the run with exit code 2 before any money is spent. Nothing paid has run.**

## What this plan does, in plain terms

Until now the scoring could only replay a saved file. This plan builds the part that goes and gets fresh listings, and it keeps the expensive decisions in one place.

1. **The run order, written once.** The script scrapes the four central districts, throws out duplicates, applies Daniel's hard filters (apartment, at least 35 m2, asking price at most 4 000 000 kr), ranks every remaining flat for free, and only then spends money: the top 20 get their detail page fetched and their pictures read. After that the list is re-sorted by profit. The function takes the scraping, detail-page and picture-reading steps as arguments, so the tests run it with fakes, and the Phase 14.2 email can call the same function instead of re-implementing the order.
2. **A guard in front of the wallet.** Before the first paid call the script estimates the worst case for the run (every page and every detail page priced at the expensive, timed-out rate: 5.90 USD for 4 districts and 20 flats) and compares it with what is left of the Apify month. Today that is 7.47 USD, so the run would start with 1.57 USD to spare. If less were left, the script prints both numbers in Swedish and English and exits with code 2 without spending anything. If Apify cannot say how much is left, it warns and goes ahead.
3. **Same output for live and replay.** Both modes print the table through the same renderer, with money rounded to whole kronor only at that last step, the position each flat had in the free ranking (Förrank), the detailed breakdown for the tracked flat (Folkungagatan 61) with its rank in innerstan and in its district, and a model-health line.

## The command plan 10 should run

```
set -o pipefail; npx tsx scripts/fit-score.ts 2>&1 | tee .planning/calibration/data/live-run-$(date +%F).log; echo "exit=$?"
```

No flags: defaults are the real model `data/hedonic-model.json`, tracked listing 150148, window 20, snapshot `.planning/calibration/data/forsale-snapshot-<date>.json`. Leave `--budget-usd` unset.

What the headroom check compares: the monthly Apify headroom from `apifyMonthlyHeadroomUsd` (the account's monthly limit minus used so far) against `estimateFitRunUsd({ districts: 4, window: 20 })` = (4 x 10 + 20 x 3) x 0.059 = **5.90 USD**. Measured today with the real token and no paid call: **7.47 USD** left, so the check proceeds. It stops with exit 2 only if the headroom is strictly below 5.90 USD. `--dry-run` runs everything up to and including the check and then stops; I ran it with the real token: exit 0 plain, exit 2 with `--budget-usd 1000`.

One thing to know before the run: `set -o pipefail` plus `tee` reports the script's exit code only through `pipefail`; `echo "exit=$?"` right after the pipe shows it.
