## Project doc-comment conventions (planner must replicate)

Every pure module in `src/lib/discovery` opens with a block comment, in this order:

1. `<filename> - one-line role`, with the spec/phase reference (e.g. "SPEC §2.6", "DISC-03").
2. PURITY statement: "PURE, synchronous - no `Date`/`Math.random`/network/async - same input always yields same output" (niche-score.ts:33-42). Zero I/O, zero model calls (flip-economics.ts:2-3).
3. STRUCTURAL SEPARATION paragraph naming the import ban in both directions: which files must never import this module (`niche-score.ts`, `report/flags.ts`) and that the static-grep test in `niche-score.test.ts` enforces it (flip-economics.ts:7-12, area-comps.ts:14-17, condition-score.ts:9-17).
4. Honesty rule: null/absent input yields "not assessable" or null, never a fabricated number (niche-score.ts:38-41, area-comps.ts:100-104).
5. All thresholds as named exported `const`s with a doc comment, not inline magic numbers (area-comps.ts:22-27; flip-economics.ts:247-253).
6. Deliberate proxies are labelled as proxies in the doc (area-comps.ts:7-13).

Other conventions: imports use the `@/lib/...` alias; `import type` for types; readonly fields on result interfaces (area-comps.ts:29-57); UI/CLI strings are Swedish, comments English; zod comes from `"zod/v4"` (candidate.ts:1).

Staleness to fix as part of the amendment (RESEARCH "Separation test amendment" item 5): header prose in `condition-score.ts:3-20`, `flip-economics.ts:7-12` says vision "never re-orders"; rewrite to "vision may influence order only through `fit-score.ts`".

## Shared Patterns

### Structural separation
**Source:** `src/lib/discovery/niche-score.test.ts:285-440` and file-level docs in `flip-economics.ts:7-12`, `area-comps.ts:14-17`.
**Apply to:** every new `src/lib/discovery/*.ts` module; each declares the ban in its header and is registered in `VISION_MODULE_SPECIFIERS`.

### Purity (no clock, no randomness, no I/O)
