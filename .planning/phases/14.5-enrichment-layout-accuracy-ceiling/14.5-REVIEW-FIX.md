## CR-01: what the Monday job does now

1. The local browser sets a latch when a Booli page is challenged for good. From then on every Booli render fails at once without opening a page, whoever asks (area pages, detail pages, BRF pages, the sold-price pull).
2. The live run switches the 5 s retry off (`retryChallenge: false`). Booli's first refusal is the last request of the run.
3. The enrichment loop and the BRF stage take a `shouldStop` hook. It is wired to `enrichStopReason`, the same rule the enrichment pull uses, fed by the Booli-only challenge count. Candidates and associations not started when the hook says stop are left unread, and the result carries `stoppedBy: "utmaning"`.
4. In local mode the four districts are pulled one after another. A block in the first district means the other three send nothing.
5. After the stage the run prints "Stopp: utmaning från Booli upptäckt ... Vänta minst ett dygn", writes `refused weekly-live` to the traffic log the Booli gate reads, prints a table line "berikning avbruten (Booli): X av Y annonser fick sin detaljsida", marks the mail's candidate-list line "berikning avbruten (Booli)" in red and bold, and exits with code 2.

Choices made that Daniel may want to overrule:

- The 5 % failure arm of `enrichStopReason` is not fed. It needs 100 attempts, which is more than a Monday run reads, and a delisted flat would count as a failure. Only the challenge arm is live.
- With the retry off, one transient challenge that a retry might have cleared now ends the Monday run. This follows the review and the brief ("the first refusal is the last request").
- The mail is still sent and the watch memory is still written after a cut-short run. The mail says it was cut short. Not changed, because the brief asked only for marking.
