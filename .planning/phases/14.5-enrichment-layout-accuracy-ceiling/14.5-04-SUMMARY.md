# Phase 14.5 Plan 04: Ceiling-height taste term, Takhöjd mail column and coverage line Summary

**A stated ceiling height of 3,0 m or more adds 1 % of resale to Daniel's taste and 3,5 m or more adds 2 %, inside the unchanged 5 % cap; the mail gets a Takhöjd column and every run prints how many descriptions stated a height**

## Accomplishments

- `ceilingTastePct` in `taste.ts` is a two-step rule: 0,01 from 3,0 m, 0,02 from 3,5 m (the higher step replaces the lower), 0 for anything else including null, NaN and "högt i tak" without a number. `tasteBonus` sums it into `pct`; the cap is still applied only in `fit-score.ts` (`TASTE_CAP_PCT` is still 0.05).
- `fitScore` passes `row.facts?.ceilingHeightM` to the taste bonus and carries `tasteCeilingPct` on every result (0 on the not-comparable branch). `rowsAtTasteCap` counts a row that reaches 5 % only because of the ceiling.
- Tracked-flat block: the Smak line ends its percentage list with "takhöjd p %", and a "Takhöjd:" line follows Planlösning.
- Mail: "Takhöjd" column right after Sovrum in the HTML and the text part, left-aligned text, escaped like every other cell.
- Coverage: `Coverage.ceiling { read, stated, tallOnly }` and one extra line after the Täckning line (before Planlösning) only when at least one description was parsed. The Täckning line is byte-identical.
- No-change proof: the 2026-10-13 snapshot replays to the same 77-flat ranking as the plan 01 baseline.
