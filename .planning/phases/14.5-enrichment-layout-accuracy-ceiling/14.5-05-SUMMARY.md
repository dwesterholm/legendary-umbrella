# Phase 14.5 Plan 05: Layout experiment runner Summary

**Five fixed layout variants (a baseline, b reworked prompt, c the same on Opus, d two-step on either tier), each with its own cache file and version, a per-model price table that fixes the Haiku-rate ledger bug, and paid modes that cannot run on an unlocked truth set or past 40 kr (smoke 1 kr); no paid call made**

## Accomplishments

- **The ledger was wrong and is fixed.** The production layout call billed a Sonnet read at Haiku prices. A read of 5 500 tokens in and 150 out now records 0,21 kr instead of 0,07 kr; a full production read with the 3 broker photos (about 9 700 tokens in) is about 0,34 kr, which matches the roughly 0,32 kr the research estimated. The lifetime ledger already stored in `layout-cache.json` is not rewritten, so it still shows the old, too-low total.
- **The four experiments are written down before anyone sees a result.** a = today's prompt on Sonnet. b = the reworked prompt (street and courtyard evidence rules, the window rules from the 14.4 eye check, "unknown is a valid answer", a plan-present check, one certainty per field) on Sonnet. c = the same prompt and schema on Opus 5.5. d = a two-step read: step A sees the plan only and names walls as drawn on the plan, step B sees the photos only and says per photo what lies outside; plain code joins them. Which tier d runs on is chosen by a rule written now: the tier whose single-step variant (b or c) had the higher mean precision on the development rows; a tie or missing data picks Sonnet.
- **Experiments cannot touch production.** Each variant has its own cache file `.planning/calibration/data/layout-exp-<id>.json` and its own version. The save function refuses the production cache and any file not named `layout-exp-<id>.json`. The production cache still holds its 75 entries, unchanged in size and modification time.
- **Money is checkpointed.** The runner hands the cache to the script after every paid call, so an interrupt or crash mid-round loses nothing already paid for, and a repeat costs 0 kr.
- **A round decision tool.** `--decide` reads every per-variant report and every variant's ledger, stops at the first variant that passes all three fields, names the next one to run, and writes a Swedish verdict with the best holdout precision per field, its interval, the rule that failed, and the total spend.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] `runVariantReads` checkpoint and estimate override**
- **Found during:** Task 2 (wiring the paid `--run` and `--smoke`)
- **Issue:** The plan says the paid round saves the variant cache "right after the run whatever happened" and caps a smoke at 1 kr. With a save only after `runVariantReads` returns, an interrupt in the middle of a 40-flat round would lose every read already paid for. With the variant's own estimate, a smoke of d-opus (1,2 kr per read) could never start under a 1 kr cap, and a smoke of c could read only one flat.
- **Fix:** Added two optional options to `runVariantReads`: `checkpoint(cache)` called after every paid call (usable read or billed failure), and `estSekPerFlat` to replace the spec's estimate for the cap test. The scripts save in the checkpoint and again in a `finally`; the smoke uses the smaller of the variant's estimate and 1 kr.
- **Files modified:** `src/lib/discovery/layout-experiment.ts`, `src/lib/discovery/layout-experiment.test.ts`, `scripts/layout-accuracy.ts`
- **Verification:** three tests in "runVariantReads: checkpoint and the smoke estimate"
- **Committed in:** `c7c7d38`

**2. [Rule 2 - Missing critical functionality] A variant cache that cannot be read is never overwritten**
- **Found during:** Task 1
- **Issue:** The plan says a bad variant cache file is never renamed. Reading it as empty and then saving would overwrite reads that were paid for.
- **Fix:** `loadVariantCache` returns `unreadable: true` for a file that is not valid JSON or has the wrong shape, and the paid `--run`, the smoke and `--report --variant` refuse to continue on it. The file is left in place.
- **Files modified:** `src/lib/discovery/layout-experiment.ts`, `scripts/layout-accuracy.ts`
- **Verification:** test "flags an unreadable file and leaves it in place"
- **Committed in:** `9b5ca22`

**3. [Rule 3 - Blocking] `layout-read.ts` needed two small additions in Task 1**
- **Found during:** Task 1
- **Issue:** The runner needs the picture count as a parameter (variants state it) and the URL list of a block set for the cache id; both were private.
- **Fix:** `layoutImagesOf` takes an optional `maxBooliPhotos` (default unchanged), and `urlsOf` became the exported `layoutBlockUrls`. Production behaviour is identical; the version constant is pinned by a test.
- **Files modified:** `src/lib/discovery/layout-read.ts`, `src/lib/discovery/layout-read.test.ts`
- **Committed in:** `9b5ca22`
