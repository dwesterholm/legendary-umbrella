<objective>
Make ANL-03 actually reachable and build its orchestrator: fix `normalizeKommun` so a Booli
genitive kommun label corroborates a registry nominative name (D-14-09), then compose a
discovery-side BRF lookup from the reusable `brf-source`/`brf` primitives — deliberately
bypassing every `analyses`-table-bound function (D-14-12).

Purpose: `resolveOrgNr` only returns `confidence: "high"` when exactly one name matches AND its
registered kommun corroborates the listing's kommun. 14-01 gave the candidate a `kommun`, but
Booli's breadcrumb yields the Swedish genitive ("Stockholms") while a registry carries the
nominative ("Stockholm") — with `normalizeKommun`'s current lowercase+trim those never match, so
the gate would stay unreachable and the whole BRF top-N would be a no-op. Fixing the
normalization is therefore part of the enablement work, not an afterthought.

Output: a genitive-tolerant `normalizeKommun` (exported for direct testing) and
`src/lib/discovery/brf-lookup.ts` exposing `BRF_TOP_N` and `lookupBrfSummary`.
No `analyses` read or write anywhere on the discovery path.
</objective>
