<objective>
Close the phase: fetch a BRF summary for the top-N prelim-ranked candidates concurrently (ANL-03),
fold its spend into the shared budget pool, and attach the holistic-data-only brief to every
candidate that leaves the vision pass with no surviving image claims (ANL-01's non-empty guarantee).

Purpose: this is the step that makes the Ringvägen 122 scenario actually produce something. It is
also the step where the Phase 13 WR-02 trap recurs — a sequential per-candidate loop of
(2 Allabrf fetches + 1 Haiku call) stacked on top of an already-slow tick would add 50-150s and risk
the ~300s Server Action ceiling, so the top-N MUST run under a bounded `Promise.allSettled` copying
`runSlice`'s own aggregation shape.

Output: `lookupBrfForTopCandidates` in `job.ts`, the final `runVisionForJob` pipeline
(enrich → comps → BRF → vision → brief → persist), and tests proving concurrency, graceful
degradation, budget sharing, and the ANL-01 guarantee across all four no-claims states.
</objective>

| Boundary | Description |
|----------|-------------|
| `candidate.brfName`/`kommun` (scraped, untrusted) → Allabrf search + document fetch | Untrusted strings influence outbound requests (delegated to `brf-lookup.ts`) |

| Aggregates → generated brief text → persisted JSONB | Numeric aggregates become user-facing prose |
