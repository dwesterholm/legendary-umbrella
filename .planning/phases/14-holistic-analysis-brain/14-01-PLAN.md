Lay the Phase 14 foundation: register the three new analysis-path modules in the LOCKED
structural-separation grep list, create the shared `holistic-schema.ts` type/read-guard module,
add the four additive-nullable persisted candidate fields (`kommun`, `areaComps`, `brfSummary`,
`holisticBrief`) with CR-01 `.nullable().default(null)` discipline, and derive `kommun` at
scrape time from the breadcrumbs already in hand (D-14-09).

consumes these types and fields. Registering the grep specifiers FIRST is mandatory — the
LOCKED separation guard is silently inert for a module whose specifier is not listed.

`confidence: "high"` and the whole BRF top-N would be a no-op behind an unreachable gate.

Output: `holistic-schema.ts` (+ tests), a 24-field `DiscoveryCandidate` allowlist, one shared
`kommunFromBreadcrumbs`, and an extended `VISION_MODULE_SPECIFIERS` array. NO DB migration.
