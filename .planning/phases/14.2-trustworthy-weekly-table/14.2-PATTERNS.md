## Project conventions (apply to every file)

- **Doc comments:** every module opens with a long `/** ... */` block that names the phase/decision IDs (D-xx, R-xx, FIT-xx, HIGH-1), says WHY each constant has its value, states "PURE, synchronous - no clock, randomness, network, async, file or environment access" where true, and a secret-posture sentence where env is read. Copy that tone (`taste.ts:1-34`, `transport.ts:3-36`).
- **Language:** logs and user-facing errors in Swedish (ASCII-only in transport errors: "Kunde inte hamta data fran Booli"), code identifiers in English.
- **Path alias:** `@/lib/...`. Scripts are CommonJS via tsx: no top-level `await`, use `async function main()`.
- **Structural-separation grep test** (`src/lib/discovery/niche-score.test.ts:326-345`): a list of specifiers (`"discovery/fit-score"`, `"discovery/hedonic-model"`, `"discovery/reno-tier"`, `"discovery/taste"`, `"discovery/fit-pipeline"`) that `niche-score.ts` / `flags.ts` must never import. Register new `discovery/listing-facts`, `discovery/watch-*`, `booli/local-browser` there.
- **24-field candidate allowlist must not grow:** `discoveryCandidateSchema` (`src/lib/discovery/candidate.ts:295-...`) mirrors `DiscoveryCandidate` and every post-Phase-9 field is `.nullable().default(null)` (never `.optional()` alone, see its CR-01 comment). R-08: new facts go in a separate `CandidateFacts` record keyed by Booli id. Do not touch `candidate.ts`'s schema or `toCandidate`'s output shape.
- **Gitignored data dir:** `.planning/calibration/data/` is ignored (`.gitignore:61`). Committed evidence goes to `.planning/phases/14.2-trustworthy-weekly-table/evidence/` (R-11).

## Pattern Assignments

### `src/lib/booli/local-browser.ts` (service, request-response)

**Analog:** `src/lib/booli/transport.ts` (the contract to honour), `fallback-tree.ts` (rung ordering and "never silently empty").

**Contract to match** (`transport.ts:68-72`):
```typescript
export async function runPlaywrightRender(
  url: string,
  pageFunction: string,
  opts?: { waitSecs?: number; maxRequestRetries?: number },
): Promise<unknown[]> {
```
Returns usable items `{ hasApollo, __APOLLO_STATE__ }`; NEVER `[]` to signal a dead source (HIGH-1, `transport.ts:25-29, 122-135`). Extract those lines into a shared `usableItems()` (RESEARCH Pattern 1) and use it from both transports so the throw messages stay identical:
```typescript
if (!items.length) throw new Error("Inga resultat fran Booli-kallan");
const usable = items.filter((it) => (it as { hasApollo?: boolean }).hasApollo !== false);
if (!usable.length) throw new Error("Booli-kallan returnerade ingen Apollo-data (hasApollo=false)");
```

**Seam in transport.ts (MOD):** add `setRenderer(fn | null)`, rename the current body to `runApifyRender` moved VERBATIM (keep `maxRequestRetries: 3`, `RESIDENTIAL/SE`, `memory: RENDER_MEMORY_MB`, `timeout: waitSecs + RENDER_TIMEOUT_GRACE_SECS`, `log: null`, and the catch that logs `console.error("[booli-transport]", error)` then throws the Swedish message; the doc comment forbids lowering the literals). `runPlaywrightRender` becomes `renderer ? renderer(...) : runApifyRender(...)`. `transport.ts` must not import `playwright`: `local-browser.ts` does `await import("playwright")` lazily; add a static-grep test that no file under `src/app`, `src/actions`, `src/components` or `transport.ts` mentions `playwright`. `new ApifyClient({ token: process.env.APIFY_API_TOKEN! })` at import time (`transport.ts:38-40`) does not throw without a token, so local-only runs still load the module.

**Running the Apify page-function string locally (R-10 trap).** The strings are whole `async function pageFunction(context)` sources (`page-functions.ts:234-238`):
```typescript
export const APOLLO_PAGE_FUNCTION = `async function pageFunction(context) {
  const { page } = context;
  const apollo = await page.evaluate(${EXTRACT_STATE_BROWSER_FN});
  return { hasApollo: apollo !== null, __APOLLO_STATE__: apollo };
}`;
```
Compile the OUTER string, never evaluate the inner `EXTRACT_STATE_BROWSER_FN` constant directly. Technique already used in tests (`page-functions.test.ts:11`):
```typescript
const extract = new Function(`return (${EXTRACT_STATE_BROWSER_FN})`)() as () => StateMap;
```
Local version: `new Function(\`return (${src})\`)()` then call with `{ page, request: { url } }` (other page functions also read `request`, e.g. `area-suggestion-page-function.ts:66-67`). Never pass a TS function literal to `page.evaluate`; pass strings only.

**Rung/fallback semantics:** `fallback-tree.ts` calls the renderer at two sites (rungs 1 and 2) and permits at most 3 rungs; `source` union is `"own-playwright" | "own-playwright-retry" | "paid-actor"`. Local mode needs no change there: a `ChallengeError` retried once inside the renderer, then Apify only with `--allow-apify`, else the usual error. Do not add a 4th rung to `walkFallbackTree` (it throws on >3).

**Error handling:** follow `transport.ts:136-143`: log the real error server-side (`console.error("[booli-local]", error)`), rethrow a Swedish user-facing message; never log env values. Refuse non-Booli URLs with `isBooliUrl` (`client.ts:508`) because `fetch-broker-page.ts:171` also calls `runPlaywrightRender` for arbitrary broker sites.

**Bounded concurrency:** reuse `runPool` from `slutpriser.ts:399` (promote it to a shared module) for task lists; the page gate is a ~10 line semaphore inside this module (project rule: no p-limit, `slutpriser.ts:393-398`).

## Shared Patterns

### One parser, two transports
**Source:** `src/lib/booli/page-functions.ts` + `transport.ts`. All Booli parsing stays in the page-function strings and `client.ts` reshape; the renderer is the only thing that differs. Do not fork the parser for local mode.

### HIGH-1: a dead source is an error, never `[]`
**Source:** `transport.ts:25-29, 122-135`; `fallback-tree.ts:20-24`. Apply to `local-browser.ts`, `brf-page.ts` caller, and the BRF fetch (missing BRF data is `null` fields on the facts record, but a failed render is a thrown error).

### Secret posture
**Source:** `transport.ts:31-35`, `scripts/fit-score.ts:342-346`. Env reported as `satt/saknas` only; catch blocks log the error object, never `process.env.*` or client instances. Applies to `WATCH_SMTP_URL`, `WATCH_EMAIL_TO`, `ANTHROPIC_API_KEY`, `APIFY_API_TOKEN`.

### Pure-module discipline and static-separation test
**Source:** `taste.ts:1-34`, `niche-score.test.ts:326-345`. Register new pure modules in the separation list.

### Atomic JSON write + gitignored data dir guard
**Source:** `scripts/fit-score.ts:140-156`.

### Bounded pool
**Source:** `slutpriser.ts:399-418` `runPool` (results in task order, rejections do not stop others, `limit` validated as integer >= 1).

### Test conventions
`vitest`; jsdom via `// @vitest-environment jsdom` first line; Apify mock via `@/lib/booli/__mocks__/apify-client`; fixtures read with `readFileSync(join(__dirname, "__fixtures__", ...))`; `console.error` spied and restored per test.
