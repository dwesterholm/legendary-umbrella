# Phase 14.2 Plan 05: Read Every Candidate for Free Summary

**A free local run now reads the detail page of all 77 comparable flats in the four districts (and 32 of their broker pages) in 203 seconds, and prints how much is actually known: balcony, avgift and tenure for 99 to 100 %, condition for 0 % until pictures are read, sun or orientation for 2,6 %.**

- **Spend:** none. Local renderer only, `--no-vision`, no Anthropic call, 0,00 USD Apify.

## Accomplishments

- `watch-enrich.ts` reads every candidate that has a listing URL: the Booli detail page, the broker page where the detail names one, and up to 4 broker photos as bytes. It follows the `enrichCandidateImages` rules (card value first, a detail balcony `true` beats a card `false`, input order kept, a failed read leaves the very same object so the pipeline can tell). `job.ts` is untouched.
- Each row carries a facts record next to the candidate: detail facts (tenure, avgift, listing age, balcony and elevator from the full amenity list) plus what the description gave (stated sun phrases, land lease, whether a description was read at all, stated facades). The description text itself is read in memory and dropped.
- `window: "all"` sends every comparable row through that read, with a 40 minute safety budget (it used 3 minutes). With Apify the window stays a number and `--window all` is refused with exit 1 and the message `--window all kräver --renderer local`.
- The district report now says how complete each list is and the run says it once: `Kandidatlista: komplett`, or `Kandidatlista: OFULLSTÄNDIG (<districts>)`. A district that failed, whose count is unknown or whose list falls short is named, never counted as complete.
- The coverage line is printed live (after the window report) and in replay (after the table), in the one shape plan 09 parses.

In plain terms: before this plan, only the top 20 flats were read and everyone else carried a default renovation cost and zero sun. Now all 77 are read, for nothing, and the run tells you what it learned and what it did not.

## What the coverage numbers mean for D-17 (before any picture is read)

Balcony, avgift, tenure and the detail page are known for 99 to 100 % of the 77 flats, so the table's money columns rest on real listing facts; condition is 0 % by construction (no picture read yet), so the 80 % condition bar depends entirely on plan 06, and sun or orientation sits at 2,6 % (2 of 77) and will not reach 80 % from listing text.

Why the sun number is that low, measured (a throwaway probe over the 36 Södermalm listings, counts only, nothing committed):

- Booli's own detail page carries no listing description at all (0 of 36). The "Booli description as fallback" therefore never fires; every description comes from the broker page.
- Only 23 of 36 broker pages gave anything and 15 gave a description. The rest are client-rendered shells, and the local renderer refuses to open non-Booli hosts (the 18 and 42 "vägrade" in the ledger are those refusals, by design, T-14.2-02). That is the 41,6 % behind "beskrivning läst".
- Of the 15 descriptions read, 1 contained the word "sol" and none stated a facade or a stated-sun phrase. So the 0 is real: brokers rarely write it. It is not a parsing miss.
