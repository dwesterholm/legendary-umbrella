## Fixed Issues

### CR-01: Closing the local renderer on a signal re-enables paid Apify rendering

**Files modified:** `src/lib/booli/local-browser.ts`, `src/lib/booli/local-browser.test.ts`
**Commit:** d3bb2ec
**Applied fix:** `close()` now installs a renderer that throws `CLOSED_RENDERER_MESSAGE` instead of restoring the Apify default, and the in-flight Apify fallback also checks the closed flag. A closed local renderer is never re-routed to Apify, with or without `allowApify`. The old test "afterwards goes back to Apify" was replaced by tests asserting refusal and `actorCall` never called, including a signal-then-keep-asking case.

### WR-01: No watchdog around a page function

**Files modified:** `src/lib/booli/local-browser.ts`, `src/lib/booli/local-browser.test.ts`, `scripts/fit-score.ts`
**Commit:** dd47752
**Applied fix:** Tab open, challenge probe, page function and tab close each race a 60 s `unref`'d timer (`LOCAL_PAGE_CALL_TIMEOUT_MS`, `PageTimeoutError`), so a hung tab fails its render, frees its semaphore slot and cannot hold the lock. New `armRunWatchdog` (2 h, closes the browser, exit code 5) is armed in `fit-score.ts`; exit code 5 is documented in the script header and the launchd README. `pull-slutpriser.ts` gets the per-page timeouts (they live in the shared renderer) but no run-level watchdog, since the review asked for it only for `fit-score.ts`.

### WR-02: Stale-lock takeover is racy, and a reused pid wedges the lock forever

**Files modified:** `src/lib/discovery/watch-state.ts`, `src/lib/discovery/watch-state.test.ts`
**Commit:** 5120e25
**Status:** fixed: requires human verification (concurrency logic)
**Applied fix:** A lock older than 6 h (`LOCK_MAX_AGE_MS`) is stale whatever its pid says. Takeover renames the stale file to a unique name (only one racer wins), checks that what it moved is what it judged stale (otherwise restores it with `link` and gives way), creates with `wx`, then re-reads the lock to confirm its own token. `release()` removes the file only when it still holds this run's record. `readRunLock` reports a too-old lock as not alive. The lock file now also holds a random `token` (extra field; older lock files still parse). A tiny window remains in which two racers could both observe the same stale lock; the rename plus content check plus final re-read close it for every ordering the tests can produce, but it is file-system logic, so please give it one human look.

### WR-03: A mail that was only written to a file still marks every flat as "seen"

**Files modified:** `scripts/fit-score.ts`, `src/lib/discovery/watch-mail.ts`, `src/lib/discovery/watch-mail.test.ts`, `scripts/launchd/README.md`
**Commit:** cb3f8cf

### WR-04: The local browser retries the same challenged page up to four times

**Files modified:** `src/lib/booli/transport.ts`, `src/lib/booli/fallback-tree.ts`, `src/lib/booli/fallback-tree.test.ts`, `src/lib/booli/local-browser.ts`, `src/lib/booli/local-browser.test.ts`
**Commit:** 9f2bb47
**Status:** fixed: requires human verification (retry policy)
**Applied fix:** The local renderer throws a `NonRetryableRenderError` once its own policy (one retry for a challenge) is used up, for refused URLs, for a closed renderer, and after a failed capped Apify fallback. `walkFallbackTree` stops on `nonRetryable === true` (duck-typed, no import). A test through `fetchListing` shows a challenged page is opened twice, not four times. Side effect to be aware of: with the local renderer every render failure (not only challenges) now ends the walk, matching D-04 ("only a challenge earns a retry"); an extraction parse failure after a successful render still gets the second rung.

### WR-05: Vision cache key ignores model, prompt and schema version

**Files modified:** `src/lib/discovery/vision-cache.ts`, `src/lib/discovery/vision-cache.test.ts`, `src/lib/discovery/vision-prompt.ts`, `src/lib/discovery/vision.ts`
**Commit:** ae313f4
**Applied fix:** `VISION_PROMPT_VERSION` is a hash of both system prompts, both model ids, the three result schemas (as JSON Schema) and a manual `VISION_LOGIC_REVISION`. It is part of the image key. The listing key is the Booli id digits (`/annons/n` and `/bostad/n` share an entry). The image key includes a digest of broker photo bytes when available (a swapped photo with the same count now misses). Entries carry `promptVersion`; entries of another version cannot be hit and are dropped on save. The two model ids moved into `vision-prompt.ts` (re-exported into `vision.ts` constants) so the cache can read them without loading the Anthropic client. Not done: age-based expiry (that is IN-06). **Cost consequence:** the first weekly run after this commit re-reads every flat once, bounded by the 60 SEK ceiling.

### WR-06: Broker-page render has no final-URL or private-address check

**Files modified:** `src/lib/booli/local-browser.ts`, `src/lib/booli/local-browser.test.ts`
**Commit:** 83369e4
**Status:** fixed: requires human verification (security boundary)
**Applied fix:** For broker pages only: fail closed if the page object lacks `route()`/`url()`; after `goto`, the final URL must be https and either the start host or a host that resolves to a public address (`isSafeExternalUrl`, injectable, verdict cached per host); every sub-request goes through a per-page route that aborts private, loopback and link-local hosts and any scheme except http(s) and inline `data:`/`blob:`/`about:`. Booli pages get no interception. Residual risk, stated in the module header: Chromium does its own DNS lookup, so a rebinding between Node's check and Chromium's lookup is narrowed, not eliminated; same-host requests are trusted because the start host was checked once. Page text is only ever parsed as data.

### WR-07: Memory fingerprint takeover can hide a genuinely new flat

**Files modified:** `src/lib/discovery/watch-state.ts`, `src/lib/discovery/watch-state.test.ts`
**Commit:** 2c1471f
**Status:** fixed: requires human verification (identity logic)
**Applied fix:** The entry stores `floor` (optional in the schema, so the existing 77-entry memory file still parses). A URL-form takeover now needs a compatible floor, an entry whose key is not owned by any row of this run (set pre-computed over all rows), and a last sighting within 14 days (`WATCH_TAKEOVER_MAX_DAYS`). Deliberate deviation from the instruction "use it in the fingerprint": the floor is used in the takeover check, not added to the fingerprint string, because changing the string would orphan every stored entry and show the whole memory as new on the next run.
