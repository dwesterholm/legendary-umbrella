# Phase 14.2 Plan 06: Pictures for Every Candidate, Capped and Cached Summary

**A weekly run now reads the pictures of every candidate in three parallel lanes capped at 20 kr each (60 kr per run, never more), flats already read are free the next time, and the first paid test on 10 real Södermalm flats cost 4,57 kr (0,46 kr per flat) with 9 of 10 getting condition claims.**

## Performance

- **Duration:** about 22 min, including two real paid runs (about 85 s each) and one free 35-flat run
- **Started:** 2026-10-13T11:02Z (approx.)
- **Completed:** 2026-10-13T11:30Z (approx.)
- **Tasks:** 2 (plus one planned follow-up folded in: broker pages in the local browser)
- **Files modified:** 10 (3 created, 7 modified)
- **Spend:** 4,57 kr (smoke run 1) + 0,41 kr (rerun) = 4,98 kr Anthropic. Apify 0,00 USD, `Apify-reserv: 0` in every run.

## Accomplishments

- **Lanes and the cap.** `runVisionChunks` deals the candidates into three lanes (every third flat each) that run at the same time. Each lane gets `60 / 3 = 20 kr` through the new `capSek` option of `runVisionPass`, so even if all three lanes spend to the limit together the run cannot pass 60 kr. The in-app cap (25 kr), `job.ts` and `VISION_ENRICH_LIMIT` (8) are untouched.
- **Cache.** `.planning/calibration/data/vision-cache.json` (gitignored) remembers each flat's picture-reading result, keyed by listing and a fingerprint of its pictures (the Booli URLs plus how many broker photos were available). Same flat, same pictures: free. New or re-photographed flat: read again, and the old entry for that flat is replaced. Only the claim text is stored, never pictures or broker descriptions.
- **One spend line**, pinned and tested: `Bildtolkning: <calls> anrop, <cache> från cache, <skipped> hoppades över, <kr> kr av tak 60 kr (delar: a/b/c kandidater)`.
- **Shared file writer.** `writeJsonAtomic` and the `--out` path guard moved out of the script into `json-store.ts`; the script keeps no copy.
- **Broker pages (the plan 05 follow-up).** The local browser used to refuse every non-Booli host, so client-rendered broker pages gave no description and no photos. It now opens a broker page when the caller passes the repo-owned broker page function and the URL is https. Search, sold-price and detail pages are still Booli-only, a broker page gets one attempt with no retry, and it never goes to Apify.

In plain terms: before this plan, a weekly run could read at most the top 20 flats' pictures and nothing was remembered. Now it can read all of them for about 35 kr the first time, a few kr in later weeks, and it will not spend more than 60 kr however many flats there are.

## Issues Encountered

- **Spend not counted for failed calls.** Money billed for a call that then failed (refusal, truncation) is counted inside `runVisionPass` against its cap but is not visible in the returned candidates, so it is missing from the Bildtolkning line. No `vision_error` occurred in either smoke run (0 hoppades över). Fixing it needs a change in `runVisionPass`'s return shape, which this plan does not touch.
- **Picture-set key is sensitive to broker photo count** (see the rerun note above). A flaky broker page costs one re-read (about 0,41 kr), never a wrong result. A softer key (Booli URLs only, broker count ignored) would avoid it at the price of not re-reading when broker photos genuinely change; left as is because the plan pins the broker count in the key.
- **`husmanhagberg.se` listing URLs log `refused second redirect`** in the direct GET (two flats per run). They then fall to the headless leg and, since broker hosts are open, were read. Pre-existing behaviour of `fetch-broker-page.ts`, out of scope.
- **Not exercised:** the cap actually binding (a lane reaching 20 kr); that is covered by unit tests with fake costs, not by a live run. The full 77-flat vision run is plan 09's evidence run.
- Test counts: `npm run test` 1 731 passed / 3 skipped (baseline 1 692 passed / 3 skipped; +39). `npx tsc --noEmit` and `npm run lint` clean.
