## Summary

The local rung is cheaper to build than D-02 suggests, because the renderer is not injected into `fit-pipeline.ts` at all. Every Booli read in the repo funnels through one function, `runPlaywrightRender(url, pageFunction, opts)` in `src/lib/booli/transport.ts`, which hands a *string* page function to the Apify actor. That string is plain JavaScript that only calls `page.evaluate`, `page.waitForTimeout`, `page.on("response")` and reads `request.url`. A local Playwright page offers the same calls, so the same strings run unchanged and all parsing downstream (`client.ts`, `slutpriser.ts`, broker parser) stays untouched. The seam is a renderer override registered by scripts only, so the in-app job keeps calling Apify with zero change in behaviour, and `playwright` never enters the Next.js server bundle.

Five things in the data will decide whether the table is trustworthy, and none of them is in CONTEXT: (1) the 14.1 scrape returned 175 / 140 / 142 / 177 listings per district, right at the 5-page cap of 180, so the candidate set was probably truncated; (2) `DiscoveryCandidate` has no avgift, listing-age, bidding or price-change field, and the detail enrichment never copied `tenureForm` or `brfName` (0 of 76 rows have them), so plan 2 needs a side-channel "facts" record, not a change to the 24-field persisted allowlist; (3) Booli's detail payload has no listing description, so sun and orientation depend on the broker page, and only 9 of 12 detail-fetched rows had a description and 0 of 12 stated an orientation, so the D-17 "sun known >= 80 %" clause will probably fail and must be reported as measured; (4) BRF debt per kvm is not in the listing payload, but Booli's public BRF page (`/bostadsrattsforening/<id>`, id sits in the listing breadcrumbs) shows total loans and bostadsrätt floor area, so debt per kvm can be computed (Booli hides its own per-kvm figure behind login); (5) this Mac is a laptop with `sleep 1`, so "stays awake" has to be made true by the job (caffeinate, plus an optional `pmset` wake).

The model decision (D-10) was reproduced for free this session: with the sign rule off, the size coefficient is +0.0461 (SE 0.0055, t = 8.4), R-squared moves 0.6058 to 0.6095 and cross-validated error 0.1157 to 0.1152. One line in `EXPECTED_SIGNS` plus three test edits does it.

**Primary recommendation:** Build `src/lib/booli/local-browser.ts` as a self-contained module that scripts install into `transport.ts` through a new `setRenderer()` hook; compile each page-function string with `new Function` and call it with `{ page, request: { url } }`; use headed Chromium (verified) positioned off-screen as the default and keep a new-headless mode (fingerprint-verified, Booli-unverified) behind a flag; carry all new listing facts in a separate `ListingFacts` record on `FitInputRow` instead of widening `DiscoveryCandidate`.

## Findings that change the plan (read first)

1. **There is no injected renderer in `fit-pipeline.ts`.** `FitPipelineDeps` is `scrape / enrich / vision` (`fit-pipeline.ts:93-107`). The scripts build those from `fetchAreaListings`, `enrichCandidateImages` and `runVisionPass`, all of which call `runPlaywrightRender`. The real choke point is `transport.ts:68-72`:
   `export async function runPlaywrightRender(url: string, pageFunction: string, opts?: { waitSecs?: number; maxRequestRetries?: number },): Promise<unknown[]>` `[VERIFIED: src/lib/booli/transport.ts:68-72]`. Callers: `client.ts:560,565,779,786,1008,1012`, `fetch-broker-page.ts:171`, `resolve-area.ts:227`, `scripts/pull-slutpriser.ts:329,510`, `scripts/probe-fit-sources.ts:179`, `scripts/probe-booli-images.ts:58` `[VERIFIED: grep this session]`.
2. **The page functions are strings that run in Node and call `page.evaluate` with a literal browser function.** `export const APOLLO_PAGE_FUNCTION = \`async function pageFunction(context) { const { page } = context; const apollo = await page.evaluate(${EXTRACT_STATE_BROWSER_FN}); return { hasApollo: apollo !== null, __APOLLO_STATE__: apollo }; }\`` `[VERIFIED: src/lib/booli/page-functions.ts:234-238]`. Other page functions also read `request`: `const { page, request } = context;` `[VERIFIED: src/lib/booli/area-suggestion-page-function.ts:66-67]`. So the local runner must pass `{ page, request: { url } }`. **Trap found by running it:** `page.evaluate(EXTRACT_STATE_BROWSER_FN)` with the exported *string* returns `undefined` (the string is a function expression that is never called); the whole outer string must be compiled and run, not the inner constant. `[VERIFIED: probe run this session, error "The data argument must be of type string ... Received undefined"]`.
3. **`playwright` is not a declared dependency.** `package.json` lists no playwright; `npm ls` shows `playwright@1.60.0`, `playwright-extra@4.3.6`, `puppeteer-extra-plugin-stealth@2.11.2` and `tsx@4.22.4` only under `promptfoo` (a devDependency), and the lockfile marks playwright `"dev": true, "optional": true` `[VERIFIED: npm ls; package-lock.json:19992-19998]`. A fresh `npm ci --omit=optional` would lose it. Declare it. Chromium revision `1223` (browserVersion `148.0.7778.96`) is what 1.60.0 expects `[VERIFIED: node_modules/playwright-core/browsers.json:5-8]` and it is installed at `~/Library/Caches/ms-playwright/chromium-1223`; `chromium-1234` belongs to a newer Playwright and is unused `[VERIFIED: ls; chromium.executablePath() printed the 1223 path]`.

D-16's premise "stays awake" is not a given.
5. **The candidate list was probably truncated in 14.1.** The live log shows `collected 177 listings for area 115353`, `175 ... 115341`, `140 ... 115348`, `142 ... 115349` `[VERIFIED: live-run-2026-10-13.log:109,222,248,272]`, and `export const MAX_AREA_PAGES = 5;` at roughly 36 listings per page gives 180 `[VERIFIED: client.ts:650; client.ts doc comment]`. 6. **Tenure and brand-new facts never reached the candidate.** The detail-merge in `enrichCandidateImages` copies only `imageUrls`, `floor`, `constructionYear`, `orientation`, `balcony` `[VERIFIED: job.ts:700-711]`. In the 2026-10-13 snapshot, `tenureForm` and `brfName` are populated on 0 of 76 rows and `constructionYear` on 11 `[VERIFIED: python count over forsale-snapshot-2026-10-13.json]`. `DiscoveryCandidate` has no avgift, published date, bidding or price-change field `[VERIFIED: candidate.ts:117-200]`.
7. **Sun cannot come from Booli's own payload.** The saved detail fixture has no top-level `description` key (the only `"description": null` is inside `priceInfo`, line 534) `[VERIFIED: listing-detail.json:528-535 and key list]`. Of 12 detail-fetched rows in 14.1, 9 had a description (broker text), 0 stated an orientation, and sun phrases were found on 0 `[VERIFIED: snapshot count: detailFetched/sunPhrases/orientation = (True,True,False) x 9, (True,False,False) x 3]`. 8. **BRF debt exists on a different Booli page.** The listing's `housingCoop` is only `{"__ref": "HousingCoop:82768"}` `[VERIFIED: listing-detail.json:121-123]` and, on the sold page probe, the `housingCoopInfo` info section has `"infoPoints":[]` with `"lazyLoad":true` `[VERIFIED: probes-2026-10-12.json result A flight]`. Debt per kvm = Lån / Boarea bostadsrätter, which is how Booli describes its own figure `[CITED: Booli BRF pages via WebSearch result]`.
9. **`.planning/calibration/data/` is gitignored** (`.gitignore:61: .planning/calibration/data/`) `[VERIFIED: git check-ignore -v]`. D-17 says the evidence HTML is "committed as `.planning/calibration/data/weekly-<date>.html`". It cannot be, without `git add -f`. Write the live file there (and `watch-state.json`, which must stay ignored), then copy the evidence HTML into the phase directory and commit that copy.
10. **The existing live script would refuse to run in local mode.** `scripts/fit-score.ts` exits 1 when `APIFY_API_TOKEN` is unset (line 346), compares `RENDER_MEMORY_MB` (line 351) and exits 2 when headroom (2.71 USD) is below the worst-case estimate (5.90 USD for 4 districts and a 20-row window) `[VERIFIED: fit-score.ts:346,351,359-361; 14.1-09-SUMMARY]`. 11. **Headless fingerprint, measured.** On `about:blank`: default headless (the `chromium_headless_shell`) reports `HeadlessChrome` in the user agent, `navigator.webdriver = true`, 0 plugins, no `window.chrome`; new headless (`channel: "chromium"`) with `--disable-blink-features=AutomationControlled` reports `webdriver = false`, 5 plugins, `window.chrome` present, but the user agent still says `HeadlessChrome/148.0.0.0`; headed matches a normal Chrome `[VERIFIED: fingerprint probe run this session]`. So the 403 on headless detail pages is explained for the default mode, and a new-headless run with a user-agent override is a plausible no-window mode. Whether Booli accepts it is untested (probe budget spent).
12. **Vision is sequential and slow.** `runVisionPass` is a plain `for` loop with a cap check before each call `[VERIFIED: vision.ts:561-633]`. The in-app run took "vision pass 20 min 04 s" for 60 results `[CITED: 14.1-10-SUMMARY.md:247-248]`, about 20 s per candidate (the per-candidate figure is my division, `[ASSUMED]` that all 60 were read). 100 candidates sequential is about 33 min; three concurrent chunks cut it to about 11 min.
13. **Dropping the size sign rule works and is cheap** (see Q5).

### Anti-Patterns to Avoid
- **Importing `playwright` from `transport.ts` or anything under `src/app`, `src/actions`, `src/components`.** The Next.js server graph imports `transport.ts` (via `client.ts`); a static Playwright import would pull a 100 MB toolchain into the bundle. Add a static-grep test next to the existing separation tests, and register `booli/local-browser`, `discovery/listing-facts`, `discovery/watch-*` in the list at `niche-score.test.ts:337-341` `[VERIFIED: niche-score.test.ts:337-341 lists "discovery/fit-score", "discovery/hedonic-model", "discovery/reno-tier", "discovery/fit-pipeline"]`.
- **Running the local rung against non-Booli URLs.** `fetch-broker-page.ts` calls `runPlaywrightRender` for arbitrary broker sites after only a DNS-address check (`fetch-broker-page.ts:160-171`). With Apify the fetch happened in Apify's cloud; locally it would be Daniel's Mac and home network, with a DNS-rebinding gap between the check and Chromium's own lookup. The local renderer must refuse anything that fails `isBooliUrl` (`client.ts:508`), which makes `fetchViaHeadless` return null (it catches); the broker direct GET path is unaffected. Cost: broker-gallery images from client-rendered broker sites are lost unless `--allow-apify`. 14.1 already lost them (`erikolsson.se` headless render failed, log line 399).
- **Treating a card `balcony: false` as "no balcony".** Existing rule R-04b.
- **`process.exit()` before the browser is closed.** The scripts call `process.exit(1/2)` in several places; close the local browser in a `finally` and avoid exiting before it.
- **Top-level `await` in scripts.** The repo is CommonJS for `.ts` files (no `"type": "module"`); tsx rejected top-level await in `-e` with `"cjs" output format`. Keep the `async function main()` pattern.

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Sending mail | A socket-level SMTP client, or shelling out to `sendmail`/`mail` | `nodemailer` with `WATCH_SMTP_URL` | TLS, AUTH, MIME multipart, dot-stuffing and encoding are where hand-rolled mail fails; no relay is configured on this Mac |

## Local rung design (Q1)

**Lifecycle.** `installLocalRenderer(opts)` calls `setRenderer(...)` and returns `{ stats(), close() }`. The browser launches lazily on the first render, one context per run, one `Page` per render, closed in `finally`. If the browser emits `disconnected`, relaunch once. `close()` runs in the script's `finally`; also register `SIGINT` and `SIGTERM` handlers that call it (launchd stops jobs with SIGTERM). Playwright talks to Chromium over a pipe, so a killed Node process takes the browser down in practice `[ASSUMED]`; the handlers are the guarantee.

**Launch settings.**
```typescript
const args = ["--disable-blink-features=AutomationControlled",
  ...(offscreen ? ["--window-position=4000,4000", "--disable-backgrounding-occluded-windows", "--disable-renderer-backgrounding"] : [])];
chromium.launch({ headless: false, args });                         // default mode "headed"
chromium.launch({ headless: true, channel: "chromium", args });     // mode "new-headless"; also set userAgent to the headed Chrome UA string
browser.newContext({ locale: "sv-SE", timezoneId: "Europe/Stockholm", viewport: { width: 1280, height: 900 }, acceptDownloads: false });
```
The off-screen window loaded a detail page with HTTP 200 in 1.3 s in this session's probe `[VERIFIED: probe "detail-572010-offscreen status 200 ms 1290" with those flags]`. It avoids a window popping up over Daniel's work. Provide `BOOLI_LOCAL_WINDOW=visible` for debugging.

**Challenge detection and retry (D-04).** Challenge = HTTP 403/429/503, or title/body containing `Vänta`, `Just a moment`, `Verify you are human`. Navigation: `page.goto(url, { waitUntil: "domcontentloaded", timeout: 45_000 })`. Because Booli streams its payload, if the extractor returns `hasApollo: false` on a 200, wait 1.5 s inside the same attempt and run it once more before calling it a challenge. On a `ChallengeError`: wait 5 s, retry once on a fresh page; if it fails again and `allowApify` is on and the Apify fallback budget (`--apify-max-renders`, default 10) is not used up, call `runApifyRender`; otherwise throw the usual Swedish error. `walkFallbackTree` then calls the renderer a second time (rung 2), so the worst case is four local attempts per URL, which costs seconds, not money.

**Pacing and concurrency.** A shared "next start time" gate (1.0-2.0 s random gap between page starts) and a semaphore of 2 (D-02). `fetchAreaListings` already fires up to 16 pages at once across four districts; the gate queues them. Per-page timeout is local to the render, not the Apify `waitSecs` (which `opts` still carries and the local runner ignores).

**Ledger.** `stats()` returns `{ pages, challenged, retried, apifyFallbacks, failed }`; the script prints "Lokal webbläsare: N sidor, 0,00 USD" and then the existing Apify runs-API line. With no fallback the runs API should report 0 runs since the start time, which is the evidence line for "free". Wait the settle delay before reading it (WR-05 fix, shared constant `LEDGER_SETTLE_MS` currently duplicated at `pull-slutpriser.ts:65` and `probe-fit-sources.ts:47`).

**Switch.** `BOOLI_RENDERER=local|apify` read by the scripts; `--renderer` overrides; default `local` for `fit-score.ts` and `pull-slutpriser.ts`. If no display is available (SSH session, `launchctl` daemon domain) the default falls back to `new-headless`, not Apify. `fit-hedonic.ts` is offline and has no renderer; its "enrichment" is `pull-slutpriser.ts --enrich` `[VERIFIED: fit-hedonic.ts:10 "NO NETWORK"; pull-slutpriser.ts:329 uses SOLD_DETAIL_PAGE_FUNCTION]`.

## Common Pitfalls

### Pitfall 1: Calling the wrong thing in `page.evaluate`
**What goes wrong:** Passing `EXTRACT_STATE_BROWSER_FN` (a string holding an uncalled arrow function) to `page.evaluate` returns `undefined`; every page then looks like a challenge.
**How to avoid:** Compile and run the outer page-function string (Pattern 2); never evaluate the inner constant directly.
**Warning signs:** `hasApollo` false on a 200 page with 1 MB of HTML. Reproduced this session.

### Pitfall 2: Playwright leaking into the Next.js build
**How to avoid:** No static import in `transport.ts` or the app tree; static-grep test; `local-browser.ts` imported only by `scripts/*`.

### Pitfall 3: Chromium build mismatch
**What goes wrong:** Upgrading `playwright` past 1.60 expects another revision (1.64.0 is current on npm).
**How to avoid:** Exact pin `1.60.0`; README line `npx playwright install chromium` for a new machine. `chromium-1234` in the cache is unrelated.

### Pitfall 4: Headed window steals focus
**How to avoid:** Off-screen window flags by default (verified 200 in 1.3 s); `BOOLI_LOCAL_WINDOW=visible` to debug; consider new-headless once proven.

### Pitfall 5: Default headless gets blocked
**What goes wrong:** The default headless shell announces itself (`HeadlessChrome`, `webdriver true`, 0 plugins); detail pages return 403 "Vänta...".
**How to avoid:** Never use `headless: true` without `channel: "chromium"`; test new-headless on three detail pages before relying on it.

### Pitfall 6: Local renderer fetching arbitrary sites
**How to avoid:** Refuse non-`isBooliUrl` URLs in the local renderer (see Anti-Patterns).

### Pitfall 7: A truncated candidate list looks like a complete one
**What goes wrong:** Five pages per district (180) silently drop listings; the table claims to rank "innerstan" but ranks a subset.
**How to avoid:** Record `totalCount` per district, raise `maxPages` for the local run until collected >= totalCount (cap 15), print "Södermalm: 241 av 241". Server-side filters would also shrink the set: `minLivingArea` is a confirmed till-salu parameter (the saved probe URL used `minLivingArea=35&maxLivingArea=36`); a price parameter such as `maxListPrice` is `[ASSUMED]` (only third-party scraper inputs were found), so verify in Wave 0 by comparing `totalCount` and card prices.

### Pitfall 8: Mailing the same row twice, or never
**How to avoid:** `notified` written only after a successful send; compare on price, not date; unit-test the five cases (new, unchanged, price up, price down, re-run same day).

### Pitfall 9: The Mac is asleep or on battery
**How to avoid:** `caffeinate -i`; README documents `pmset repeat`; the job prints start and end timestamps so a late run is visible in the log.

### Pitfall 10: "Sun known" gamed or guessed
**How to avoid:** Report two numbers: description read, orientation/sun stated. Extend the keyword extractor only with phrases a broker states (`morgonsol`, `förmiddagssol`, `eftermiddagssol`, `kvällssol`; `[ASSUMED]` that they are common), never infer from the address. If the stated share stays under 80 %, the D-17 sun clause is reported as not met and 14.3 opens.

### Pitfall 11: HTML injection through scraped or model-written text
**How to avoid:** `escapeHtml` on every dynamic string; clamp vision claim length; test with `<script>` and `&` in an address.

### Pitfall 12: Evidence file lands in a gitignored directory
**How to avoid:** copy the evidence HTML to `.planning/phases/14.2-trustworthy-weekly-table/evidence/` and `git add` that path; keep `watch-state.json` where it is.

### Pitfall 13: Two runs at once
**How to avoid:** a PID lock file next to the state (`watch-state.lock`); a manual run during the scheduled run exits with a clear message.

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Local browser fetching an internal or attacker-chosen host via a broker URL (SSRF / DNS rebinding) | Elevation / Information disclosure | Local renderer refuses non-Booli URLs; broker direct GET keeps its resolve-then-pin guard |
| Script injection through listing text or LLM claims in the HTML mail | Tampering | `escapeHtml`, no remote content, no images, length clamps |
| SMTP password leaking into logs, the plist, or the committed evidence | Information disclosure | env only; mask in logs; grep the evidence HTML and log for the env name and `smtps://` before committing |
| Booli page JavaScript running on Daniel's Mac | Elevation | Normal browsing risk; fresh context per run, `acceptDownloads: false`, no persistent profile, no cookies stored |
| State file tampering or corruption causing mass re-mail | Tampering | zod parse, fall back to empty, print a warning, atomic writes |
| Runaway spend through the Apify fallback | Denial of wallet | `--allow-apify` off by default, `--apify-max-renders` cap, headroom check kept for that mode |
