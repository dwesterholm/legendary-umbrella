# Phase 14.2 Plan 08: Seen-Listing Memory, Mail Renderer and Delivery Summary

**`--email` now remembers every flat's first-seen date and last asking price in a gitignored watch-state.json, mails (SMTP via pinned nodemailer 9.0.5) or files (weekly-<date>.html) only new and price-changed flats, stays silent on a quiet week, refuses to overlap with another run, and writes its memory only after delivery.**

- **Duration:** 29 min (about 12 of them two real local-browser runs)
- **Started:** 2026-10-13T11:40:41Z
- **Completed:** 2026-10-13T12:10Z

- **Files modified:** 14

## Accomplishments

- **Memory (D-14):** `watch-state.json` keyed by the listing path, with a fingerprint fallback so a flat that switches between `/annons/<n>` and `/bostad/<n>` is not "new". Price change means both prices known and at least 1 kr apart. 90-day prune. A corrupt file is read as empty, renamed to `.bak-<timestamp>`, and the next mail falls back to first-run mode (top 15 per section).
- **Mail (D-15, W2, R-01):** pure HTML and text from the same rows. New rows say exactly `nya sedan förra veckan`, changed rows exactly `prisändrad (3 995 000 → 3 795 000)`. Full column set with "Varför här", header with date, candidate-list completeness, coverage line and model line. No images, scripts or remote content.
- **Delivery (R-02):** `sendWatchMail` through nodemailer from `WATCH_SMTP_URL` / `WATCH_EMAIL_TO` (optional `WATCH_EMAIL_FROM`, default the recipient). Without them the HTML goes to `<state dir>/weekly-<date>.html` and the run says which variable is missing.
- **Run control:** exit 3 when another live run holds `watch-state.lock`, exit 4 when delivery fails (HTML written, memory untouched), `--dry-run --email` prints `Renderare`, `WATCH_SMTP_URL`, `WATCH_EMAIL_TO`, `watch-state`, `Lås` in that order without scraping, launching a browser or taking the lock.
- **R-14 applied:** `ovanlig planlösning` only from 2 rooms (it fired on 10 of 35 rows before, all 1-room flats). On today's live table it fires on 0 of 77.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Two different flats collapsed into one by the fingerprint rule**
- **Found during:** the first real run (Task 3 verification, not catchable with the fixtures)
- **Issue:** Gyllenborgsgatan 15, Kungsholmen, 38 kvm appears twice in today's data: `/bostad/328408` (3 295 000 kr, floor 2, 1 room) and `/bostad/328402` (3 695 000 kr, floor 2.5, 2 rooms).
